## 一、阶段界定

### 1.1 本阶段与相邻阶段的边界

第 1～8 阶段已全部完成并各自通过门禁。上游给本阶段的接口是明确的：第 7 阶段交出「最终证据集合 ＋ 图谱载荷 ＋ Prompt 区块适配」，第 8 阶段交出「带引用编号的答案 ＋ 证据绑定 ＋ 记录层（question／answer／answer_evidence 三表语义的 JSONL）」。

本阶段处理的**只有一件事**：把已经跑通的四条 Python 链路（数据准备、抽取与图谱、检索、问答）**装进一个单体后端 ＋ 一个前端页面 ＋ 三个数据存储**，使《02》第6.2节 的六个功能模块（FR-01～FR-06）在**服务与页面上**可用、可演示、可被第 10 阶段的实验运行器调用。

| 边界 | 内容 | 归属 |
| --- | --- | --- |
| 上游（已完成，只读） | 数据集 v2.1（709 篇／5018 块／5018 向量）、图谱导出 `v2.1_v1_2`（2802 节点／2736 边）、`检索产出\` 六件、`问答产出\` 七件、`代码\检索\` 与 `代码\问答\` 的全部模块 | 第 5～8 阶段 |

**一句话边界**：本阶段交付的是「**六个模块在服务和页面上真的能用**」——接口可调、页面可点、数据真的落到了 MySQL 与 Neo4j；第 10 阶段在这套系统上跑实验，第 11 阶段把这套系统写成论文的第五、六章。

### 1.2 本阶段在校验链路上的位置（不得越界的一条）

本阶段**不产生方法层面的实验结论**：问答答案仍由第 8 阶段冻结的配置生成（`deepseek-flash`／`temperature=0`／`max_tokens=16384`／Prompt v1.0），检索仍由第 7 阶段冻结的定值驱动（K=10／N=20／预算=3600／g=2）。**接口层不提供 A～E 组的切换能力**：普通用户接口 `/api/qa/ask` 固定使用 Method（C 组），消融与对比实验只能经受控实验入口 `/api/admin/experiment/ask` 调用（《10》第4.7.1节 的既有口径，本阶段照此实现并加机检）。

### 2.3 本阶段必须遵守的硬口径（一律以《02》与《10》为准，本阶段不重新论证）

1. **六张表恒为六张**：user／document／document_chunk／question／answer／answer_evidence；表数量、字段名与字段职责以《10》第4.4.1节 表 4-6 为准，**不新增字段、不新增表**。
2. **`(answer_id, chunk_id)` 联合主键**；`document_chunk` 的 `uk_chunk_doc_index(doc_id, chunk_index)` 唯一；`fk_ae_doc`／`fk_ae_chunk` 为 **RESTRICT**。
3. **历史证据保护**：已被 `answer_evidence` 引用的文档禁止物理删除、禁止原地修改；删除请求只使其「不可再用于新检索」，修改须以**新 doc_id** 重新导入并把旧记录置为不可再用于新检索；两者都返回 **2003（HTTP 409）** 与 `retained_for_history = true`（《10》第4.4.2节、第4.7.3节）。
4. **`data_cutoff_time` 不属于任何表**，是数据集版本级属性；涉及相对时间的响应都返回它，页面固定显示「数据截至：YYYY-MM-DD」。
5. **`session_id` 是 question 表的字段而不是新表**；第一版不启用登录，历史记录按 `session_id` 过滤，`user_id` 为空。
6. **`answer.graph_path` 以 JSON 文本存储**，不建独立路径表；回看只还原 question／answer／answer_evidence 三表内容，**不重新渲染**图谱路径。
7. **0 跳或未启用图谱扩展时**：`graph_path` 为空、`is_graph_extended = 0`，证据区块显示固定字样**「本次回答未使用图谱扩展」**，不得留空、不得虚构路径。
8. **公开事实与模型分析必须区分**：开放式分析问题同屏标注「模型分析（非公开事实）」，且不计入任何指标。
9. **普通用户接口不提供 A～E 组切换**；`/api/config/meta` 只读返回 dataset_version／data_cutoff_time／prompt_version／k／n／context_token_budget／model_name。
10. **2002（HTTP 200）不是错误**：图谱查询为空、历史记录为空按正常业务状态返回，由前端提示。
11. **术语纪律**：FAISS 一律称「向量索引」或「向量检索组件」；不得出现被禁的四字连写术语。
12. **技术栈不得越界**（《02》第8.4节）：不引入 LangChain／LlamaIndex／Elasticsearch／Kafka／微服务／K8s／**容器编排系统**／Agent 自主编排／多模态与语音／实时行情；Docker 只用于**统一运行环境**。

《02》第12.4节 的八项实验配置已由第 8 阶段**全部落定**，本阶段**不再改动任何一项**。本阶段要固化的是三项**工程口径**，并随收口登记进《02》**v3.4**：

## 五、编写口径与硬约束（可机器核验）

1. **参数一律取配置**：脚本与后端代码内不得写死库名、连接串、端口、路径、K／N／预算／g、模型名与版本、日期；四项检索定值与生成侧配置**从 `代码\检索\config.py` 与 `代码\问答\config.py` 导入**。
2. **密钥纪律**：数据库口令与大模型密钥只从环境变量或 `代码\后端\config.local.json` 读；**不写死、不回显、不入库、不进日志、不进前端构建产物**；缺失即以明确错误退出。
3. **六表不增减**：表名、字段名、类型与约束逐字对齐《10》第4.4.1节 表 4-6；**不新增表、不新增字段、不建 history 表**。
4. **导入幂等**：`tools\import_data.py` 与 `tools\import_graph.py` 重复运行不产生重复行（按主键 upsert 或先清后插并留痕），第二次运行的库内计数与第一次一致。
5. **历史证据保护必须真的生效**：删除／修改被 `answer_evidence` 引用的文档返回 **2003** 且 `retained_for_history=true`；数据库层由 **RESTRICT** 外键兜底（机检：直接 DELETE 应被数据库拒绝）。
6. **2002 是正常状态**：图谱查询为空、历史为空返回 HTTP 200 ＋ 空结果标记，不得返回 4xx／5xx。
7. **错误响应不含 detail**：HTTP 响应体只有 `code` 与 `message`；`detail` 只写后端日志（机检：响应体键集）。

## 六、我已预先定下的格式决策

1. **后端目录形态**：`代码\后端\` 下 `api\`（按模块分文件）／`services\`（跨模块编排）／`tools\`（导入与运维脚本）／`schema\`（DDL）；**不写 ORM 模型类**，表结构以 SQL 为准，避免「两处定义、各自漂移」。

3. **响应体形态**：成功响应 `{ "data": …, "meta": { "dataset_version": …, "data_cutoff_time": … } }`；错误响应 `{ "code": …, "message": … }`；分页统一 `{ "total": …, "items": […], "page": …, "page_size": … }` 放在 `data` 内。

5. **图谱可视化**：前端用**轻量自绘**（SVG／Canvas 布局，不引入大型可视化框架），数据来自 `/api/graph/*`；节点与边的证据属性在侧栏展示。
