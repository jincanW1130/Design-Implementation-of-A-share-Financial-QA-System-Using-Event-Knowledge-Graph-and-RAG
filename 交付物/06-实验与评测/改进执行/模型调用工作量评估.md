# 模型调用工作量评估（免人工方案）

> 回答口述问题："不用人工、只用模型"时，各项"需模型调用"的**调用量 / 耗时 / 改动量**。
> 全部数字基于既有运行台账**实测推算**（非估算拍脑袋）；口径：零人工、全部以模型完成。
> 编制：2026-10-10。落点：`交付物/06-实验与评测/改进执行/`。

---

## 〇、一条决定性结论（先看这个）

**检索侧全链可以做到 ≈ 0 次模型调用**——因为 `run_query.py` 是本地零调用运行器
（本地 Embedding 前向 ＋ 读图谱 CSV；自带 "external_api_calls: 0" 记账）。

因此"需模型调用"的只剩三处：
1. **重跑抽取本身**（仅当要改抽取 Prompt 真重跑时）；
2. **答案文本生成**（只有答案质量指标需要，检索指标不需要）；
3. **评审/判决**（评分、复核、校准）。

**实测基准**（来自既有台账，供直接换算）：

| 基准项 | 实测 |
| --- | --- |
| 抽取 | 709 文档 = **747 次调用** / 5.15M tokens / 3.3h（v2.1 全量，含 38 次压缩重试） |
| 答题 | 正式集 702 条有效答案 = **703 次调用** ≈ 1 次/题（14.99s/题均值） |
| 评分 | 正式集评分 = **2,383 次调用** / 12.2M tokens / 累计延迟 8.2h（3 分片并行） |
| 检索重跑 | **0 次**（全本地计算） |

## 二、三种套餐建议（按"投入产出比"排序）

### 套餐甲（推荐 · 均衡）
**A-3 模型版 ＋ A-4 ＋ A-1 后处理版（+下游零调用验证）＋ F1 复评**

| 指标 | 估算 |

## 四、需要你拍板的 3 个决定点

1. **F1 主评审的 temperature 问题**（kimi 端点拒收 temp=0；zhipu 已支持且现为副评审）。
   三选一：① 主评审换 zhipu（原生 temp=0，最干净）；② kimi 保持主评审、三重复取众数
   （调用量↑50%）；③ 两家并列为"双主评审"。
2. **评分预算上限**：正式评分有自设上限 3,600 次/轮（实际用 2,383）；F1 需提到 ≥6,000。
3. **启动范围**：按套餐甲 / 乙 / 丙哪一档开跑；或指定条目组合。

> 说明：调用量均为"上限估算"（含约 10% 重试）；成本按各端点单价乘 token 数自行核算。
> 所有运行不留人工环节；产出全部落 `改进执行/`，与冻结读数并存、不得互相替换。
