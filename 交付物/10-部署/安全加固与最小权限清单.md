## 2. 目标状态

1. **运行期 MySQL 账号只做 DML**：`SELECT/INSERT/UPDATE/DELETE ON ashare_qa.*`，
   无 DDL、无账号管理、无 `GRANT OPTION`。
2. **建表/导入使用独立迁移账号或 DBA 手工执行**：运行期账号不需要 `CREATE/DROP/ALTER`。
3. **MySQL 只监听本机**（单机部署）或仅对受信网段开放；33060 不需要则关闭。
4. **Neo4j 只监听本机**；默认管理员口令轮换；如版本支持则使用专用只读/读写账号；
   Community 版以网络隔离与独立实例替代细粒度 RBAC。
5. **后端绑定 127.0.0.1，由 Nginx 对外提供 TLS 与静态前端**；不对外暴露 5173。
6. **密钥只来自**：操作系统环境变量、受控的本地配置文件（ACL 收紧）或密钥管理服务；
   不进镜像、不进 git、不进日志。
7. **admin_token ≥32 字符随机串**，定期轮换；所有运维脚本从环境变量读取。
8. **配置分层**：`ASHARE_ENV` 选择环境 → `config.<env>.local.json` 覆盖默认值 →
   `ASHARE_*` 环境变量白名单覆盖；生产优先用环境变量/密钥管理。

> 运行期 DML-only 账号可行的前提：`run.py` **不会**调用 `ensure_database()` 或
> `init_schema()`，只在 `tools/import_data.py` 中建库建表。因此先由 DBA 创建好库表，
> 再用 DML-only 账号启动后端即可。

## 3. 执行清单（建议在维护窗口执行）

> 每步都给出验证与回滚。**不要一次性全部执行**；按“先只读验证、再小步变更”的顺序。

### 3.1 准备与备份

- [ ] 备份 MySQL：`mysqldump --single-transaction --routines --triggers ashare_qa > ashare_qa_before_privilege.sql`
- [ ] 备份 `config.local.json` 到受控位置（不要放进仓库）。
- [ ] 记录当前 `SHOW GRANTS`、`SHOW VARIABLES LIKE 'bind_address'`、Neo4j `SHOW CURRENT USER`。
- [ ] 确认维护窗口内无长问答在跑（观察 `/api/health` 与 `qa_runs`）。

回滚：恢复上述备份与配置，重启服务；权限变更可用 `REVOKE` 反向撤销。

### 3.2 MySQL 最小权限账号（骨架，不在本轮执行）

由 DBA/root 在维护窗口执行；口令用 `Read-Host -AsSecureString` 或密钥管理生成，**不要**用示例值。

```sql
-- 1) 运行期 DML-only 账号（仅本机）
CREATE USER 'ashare_app'@'127.0.0.1' IDENTIFIED BY '<NEW_STRONG_PASSWORD>';
GRANT SELECT, INSERT, UPDATE, DELETE ON `ashare_qa`.* TO 'ashare_app'@'127.0.0.1';
-- 不需要：CREATE/DROP/ALTER/INDEX/REFERENCES/GRANT OPTION/FILE/PROCESS/SHUTDOWN
SHOW GRANTS FOR 'ashare_app'@'127.0.0.1';

-- 2) 迁移账号（只在建表/导入时启用；用完可 LOCK/删除）
CREATE USER 'ashare_migrator'@'127.0.0.1' IDENTIFIED BY '<ANOTHER_STRONG_PASSWORD>';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, DROP, ALTER, INDEX, REFERENCES
  ON `ashare_qa`.* TO 'ashare_migrator'@'127.0.0.1';
SHOW GRANTS FOR 'ashare_migrator'@'127.0.0.1';
```

说明：

- `import_data.py` 会调用 `ensure_database()`（`CREATE DATABASE IF NOT EXISTS`）。
  若迁移账号没有全局 `CREATE`，请先由 DBA 手工建库：
  `CREATE DATABASE IF NOT EXISTS ashare_qa CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;`
  然后确认 `CREATE DATABASE IF NOT EXISTS` 在该账号下仍被允许；不被允许时，导入仍由
  DBA/root 执行，**不要**为此给运行期账号加全局权限。
- 切换后端配置（本地或环境变量，二选一）：

```json
{
  "mysql_user": "ashare_app",
  "mysql_password": "<NEW_STRONG_PASSWORD>"
}
```

```powershell
$env:ASHARE_MYSQL_USER = "ashare_app"
$env:ASHARE_MYSQL_PASSWORD = "<NEW_STRONG_PASSWORD>"   # 由密钥注入，不写盘
python 交付物\03-代码\后端\run.py
```

- 验证：
  - `GET /api/health` 的 `mysql.ok=true`；
  - `GET /api/history?session_id=...` 200；
  - 在维护窗口发一次问答，确认 `question/answer/answer_evidence` 写入；
  - `SHOW GRANTS FOR 'ashare_app'@'127.0.0.1'` 只含四条 DML。
- 回滚：把配置改回原账号并重启；`REVOKE`/`DROP USER 'ashare_app'@'127.0.0.1'`。
- **注意**：任何联调写入后用 `DELETE FROM ... WHERE question_id>30` 清理，保持
  `question=30 / answer=30 / answer_evidence=293` 基线。

### 3.3 MySQL 网络收敛

- [ ] 编辑 MySQL 配置文件（Windows 通常为 `my.ini`），设置 `bind-address=127.0.0.1`。
- [ ] 如不需要 X Protocol，关闭 `mysqlx` 或将其绑定到 127.0.0.1（默认 33060）。
- [ ] 重启 MySQL 服务（维护窗口）。
- [ ] 验证：`netstat -ano | findstr :3306` 只出现 `127.0.0.1:3306`；
      `GET /api/health` 仍为 ok。
- [ ] 若必须远程访问：只对受信网段开放 3306，并在防火墙限制来源；优先走 SSH 隧道/VPN。

回滚：恢复 `bind-address=*` 并重启。

### 3.4 Neo4j 最小权限与网络

现状：Community 版 `SHOW ROLES` 不支持，无法按标签/属性做细粒度授权。

- [ ] 轮换默认 `neo4j` 口令为 ≥16 字符随机串（通过 `neo4j-admin dbms set-initial-password`
      或首次登录后的 `ALTER CURRENT USER SET PASSWORD`，按所用版本执行）。
- [ ] 确认 `dbms.connector.bolt.listen_address=127.0.0.1:7687`、
      `dbms.connector.http.listen_address=127.0.0.1:7474`；`server.default_listen_address=127.0.0.1`。
- [ ] 防火墙仅允许本机访问 7474/7687。
- [ ] 如使用 Enterprise 或支持角色管理的构建（**骨架，不在本轮执行**）：

```cypher
// 仅在企业版/支持角色管理的版本执行；Community 版会报 UnsupportedAdministrationCommand
CREATE USER ashare_app SET PASSWORD '<NEW_STRONG_PASSWORD>' CHANGE NOT REQUIRED;
GRANT ROLE reader TO ashare_app;
SHOW CURRENT USER;
```

- [ ] 验证：用新账号/新口令执行只读查询；`GET /api/health` 的 `neo4j.ok=true`。
- [ ] 回滚：恢复原口令/配置并重启 Neo4j；保留旧口令到验证完成后再销毁。

> 若升级 Enterprise 成本高：保持“独立实例 + 仅本机 + 防火墙 + 只读副本/快照”的组合，
> 并在答辩中如实说明 Community 版的 RBAC 限制。

### 3.5 admin_token 轮换

- [ ] 生成 ≥32 字符随机串（PowerShell 示例，输出只进环境变量）：

```powershell
$bytes = New-Object byte[] 32
[System.Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
$token = [Convert]::ToBase64String($bytes)
$env:ASHARE_ADMIN_TOKEN = $token
```

- [ ] 写入本地配置或环境变量；重启后端。
- [ ] 验证：
  - 无令牌 `GET /api/admin/consistency-check` → 401／4001；
  - 前端来源 → 403／4002；
  - 带正确令牌 → 200；
  - 日志中不出现令牌取值（只比对，不打印）。
- [ ] 更新运维/实验脚本，让它们从 `ASHARE_ADMIN_TOKEN` 读取；不要硬编码。
- [ ] 旧令牌在验证完成后作废；记录轮换日期（不记录取值）。
- 回滚：恢复旧令牌并重启；旧令牌在确认新令牌可用前不要销毁。

### 3.6 配置文件与 ACL

- [ ] 确认 `config.local.json` 仍在 `.gitignore` 中且未被跟踪：
      `git check-ignore -v 交付物\03-代码\后端\config.local.json`；
      `git ls-files --error-unmatch 交付物\03-代码\后端\config.local.json` 应失败。
- [ ] 收紧 ACL（可选，执行前确认不会阻断当前运行/沙箱）：

```powershell
icacls "C:\...\交付物\03-代码\后端\config.local.json" /inheritance:r `
  /grant:r "$env:USERNAME:(F)" "SYSTEM:(F)" "Administrators:(F)"
icacls "C:\...\交付物\03-代码\后端\config.local.json"
```

- [ ] 若 `icacls` 变更影响当前进程，立即恢复继承或加入所需主体；这是本清单中**最容易
      误伤运行环境**的一步，建议最后做。
- [ ] 确认 `config.docker.json`、`.env.example`、Dockerfile 中没有真实密钥；
      容器部署用 `env_file` 或 Docker secrets，不要把 `config.local.json` 打进镜像。

### 3.7 对外服务与 TLS

- [ ] Uvicorn 绑定 `127.0.0.1:8000`（或容器内网），由 Nginx 反代。
- [ ] Nginx 启用 TLS；只代理 `/api/`，静态前端由构建产物提供。
- [ ] 关闭/限制 5173；生产不使用 Vite 开发服务器。
- [ ] 复核 CORS 只保留实际域名；不要在 Nginx 层放开 `*`。
- [ ] 复核 `X-Forwarded-For`：只有确认在可信反代后才设 `trust_proxy_headers=true`。
- [ ] 复核限流在反代后按真实客户端 IP 生效（`TRUST_PROXY_HEADERS` + 代理头清洗）。
