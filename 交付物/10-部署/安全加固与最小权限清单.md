## 2. 目标状态

1. **运行期 MySQL 账号只做 DML**：`SELECT/INSERT/UPDATE/DELETE ON ashare_qa.*`，
   无 DDL、无账号管理、无 `GRANT OPTION`。
2. **建表/导入使用独立迁移账号或 DBA 手工执行**：运行期账号不需要 `CREATE/DROP/ALTER`。
3. **MySQL 只监听本机**（单机部署）或仅对受信网段开放；33060 不需要则关闭。
4. **Neo4j 只监听本机**；默认管理员口令轮换；如版本支持则使用专用只读/读写账号；
   Community 版以网络隔离与独立实例替代细粒度 RBAC。
5. **后端绑定 127.0.0.1，由 Nginx 对外提供 TLS 与静态前端**；不对外暴露 5173。
6. **密钥只来自**：操作系统环境变量、受控的本地配置文件（ACL 收紧）或密钥管理服务；
   不进镜像、不进 git、不进日志。
7. **admin_token ≥32 字符随机串**，定期轮换；所有运维脚本从环境变量读取。
8. **配置分层**：`ASHARE_ENV` 选择环境 → `config.<env>.local.json` 覆盖默认值 →
   `ASHARE_*` 环境变量白名单覆盖；生产优先用环境变量/密钥管理。

> 运行期 DML-only 账号可行的前提：`run.py` **不会**调用 `ensure_database()` 或
> `init_schema()`，只在 `tools/import_data.py` 中建库建表。因此先由 DBA 创建好库表，
> 再用 DML-only 账号启动后端即可。

### 3.2 MySQL 最小权限账号（骨架，不在本轮执行）

由 DBA/root 在维护窗口执行；口令用 `Read-Host -AsSecureString` 或密钥管理生成，**不要**用示例值。

```sql
-- 1) 运行期 DML-only 账号（仅本机）
CREATE USER 'ashare_app'@'127.0.0.1' IDENTIFIED BY '<NEW_STRONG_PASSWORD>';
GRANT SELECT, INSERT, UPDATE, DELETE ON `ashare_qa`.* TO 'ashare_app'@'127.0.0.1';
-- 不需要：CREATE/DROP/ALTER/INDEX/REFERENCES/GRANT OPTION/FILE/PROCESS/SHUTDOWN
SHOW GRANTS FOR 'ashare_app'@'127.0.0.1';

-- 2) 迁移账号（只在建表/导入时启用；用完可 LOCK/删除）
CREATE USER 'ashare_migrator'@'127.0.0.1' IDENTIFIED BY '<ANOTHER_STRONG_PASSWORD>';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, DROP, ALTER, INDEX, REFERENCES
  ON `ashare_qa`.* TO 'ashare_migrator'@'127.0.0.1';
-- 备份的导入回验会建/删 ashare_qa_bakverify_<时间戳> 临时库；只授权 ashare_qa.* 不够
GRANT CREATE, DROP ON `ashare_qa_bakverify_%.*` TO 'ashare_migrator'@'127.0.0.1';
SHOW GRANTS FOR 'ashare_migrator'@'127.0.0.1';
```

说明（2026-10-19 独立审查后更新）：

- `import_data.py` 调用的 `db.ensure_database()`／`db.init_schema()` 现在**先检查库表是否已存在**：
  库已存在、六表齐全时**完全不发 DDL**，因此 DML-only 运行期账号也能执行导入的写入部分。
  只有缺库／缺表时才需要迁移账号；缺权限时 `db.py` 会以 SystemExit 给出迁移账号提示，
  不再抛裸 1044/1142。
- 若迁移账号没有全局 `CREATE`，请先由 DBA 手工建库：
  `CREATE DATABASE IF NOT EXISTS ashare_qa CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;`
  然后确认 `CREATE DATABASE IF NOT EXISTS` 在该账号下仍被允许；不被允许时，导入仍由
  DBA/root 执行，**不要**为此给运行期账号加全局权限。
- 备份脚本（`工具\备份.py`）真实运行会**先建/删一个探针库**验证 CREATE/DROP，再写任何文件。
  权限探测结果决定回验模式（2026-10-19 P2/P3 清理后）：
  - **有 DDL 权限**：照旧完成导入回验，manifest `verify.verified=true`、`counts_match=true`；
  - **DML-only（无 DDL）**：自动跳过回验，manifest 写 `verified=false`、
    `verify_skipped_reason="no DDL privilege"`，**退出码 0**（定时任务不再误报失败）；
  - **严格模式** `python 工具\备份.py --require-verify`：无 DDL 权限时退出 1，不产生半成品目录。
  - 推荐用迁移账号环境变量运行完整回验（不改 `config.local.json`）：
  ```powershell
  $env:ASHARE_MYSQL_USER = "ashare_migrator"
  $env:ASHARE_MYSQL_PASSWORD = "<MIGRATOR_PASSWORD>"
  python 工具\备份.py
  ```
  也可显式 `python 工具\备份.py --skip-verify`：备份文件仍生成，manifest 写
  `verified=false`、`verify_skipped_reason="--skip-verify"`，不得把它当作「已回验」的备份。
- 切换后端配置（本地或环境变量，二选一）：

```json
{
  "mysql_user": "ashare_app",
  "mysql_password": "<NEW_STRONG_PASSWORD>"
}
```

```powershell
$env:ASHARE_MYSQL_USER = "ashare_app"
$env:ASHARE_MYSQL_PASSWORD = "<NEW_STRONG_PASSWORD>"   # 由密钥注入，不写盘
python 交付物\03-代码\后端\run.py
```

- 验证：
  - `GET /api/health` 的 `mysql.ok=true`；
  - `GET /api/history?session_id=...` 200；
  - 在维护窗口发一次问答，确认 `question/answer/answer_evidence` 写入；
  - `SHOW GRANTS FOR 'ashare_app'@'127.0.0.1'` 只含四条 DML。
- 回滚：把配置改回原账号并重启；`REVOKE`/`DROP USER 'ashare_app'@'127.0.0.1'`。
- **注意**：任何联调写入后用 `DELETE FROM ... WHERE question_id>30` 清理，保持
  `question=30 / answer=30 / answer_evidence=293` 基线。

### 待执行步骤（需管理员权限／维护窗口）

#### A. MySQL `bind_address` 收敛（本会话明确不做：无提权）

1. **备份配置**（管理员 PowerShell）：
   `Copy-Item 'C:\ProgramData\MySQL\MySQL Server 8.4\my.ini' 'C:\ProgramData\MySQL\MySQL Server 8.4\my.ini.bak-before-bind'`
2. 在 `my.ini` 的 `[mysqld]` 段加一行：`bind-address=127.0.0.1`
   （若已有 `bind-address`，改为该值；不要动端口与数据目录）。
3. 重启服务：`Restart-Service MySQL84`（或 `net stop MySQL84 && net start MySQL84`）。
4. **校验**：`SHOW VARIABLES LIKE 'bind_address'` 应为 `127.0.0.1`；
   `Get-NetTCPConnection -LocalPort 3306 -State Listen` 的 `LocalAddress` 应为 `127.0.0.1`
   而非 `0.0.0.0`／`::`；随后跑一次 `python 工具\备份.py --dry-run` 与
   `GET /api/health`（`mysql=true`）。
5. **回滚**：先 `Restart-Service MySQL84` 前把备份的 `my.ini.bak-before-bind` 覆盖回 `my.ini`，
   再重启服务；用第 4 步同样的命令确认监听恢复原状。本仓库无需改动（后端始终连
   `127.0.0.1:3306`，收敛前后均可达）。

#### B. Neo4j 默认管理员／RBAC（本会话明确不做：Community 无细粒度角色，轮换会中断图谱）

> Community Edition 不支持 `CREATE ROLE`／细粒度权限；「RBAC」在此版本只能靠
> **网络隔离＋独立实例**实现。下列步骤只做管理员口令轮换，**不虚构角色授权**。

1. **维护窗口与备份**：暂停后端写入流量（或停后端进程）；在 WSL 内备份 Neo4j 的
   `data/dbms/auth`（实际路径以容器挂载为准）：
   `wsl -d Ubuntu -u root -- bash -lc "docker inspect ashare-neo4j --format '{{json .Mounts}}'"`
   记下数据卷路径后 `cp -a <data>/dbms/auth <data>/dbms/auth.bak-before-rotate`。
2. **轮换口令**（二选一）：
   - 已有实例：`cypher-shell -u neo4j -p '<OLD>' "ALTER CURRENT USER SET PASSWORD FROM '<OLD>' TO '<NEW_STRONG_PASSWORD>'"`；
   - 尚未初始化认证：启动前执行
     `neo4j-admin dbms set-initial-password '<NEW_STRONG_PASSWORD>'`（只在首次设置时有效）。
3. **同步应用配置**：把新口令写入本机 `config.local.json` 的 `neo4j_password`
   （或进程环境变量；不写盘、不入日志、不进 git），重启后端。
4. **校验**：`GET /api/health` 的 `neo4j=true`；`/api/graph/*` 读路径 200；
   `cypher-shell -u neo4j -p '<NEW>' "RETURN 1"` 成功；旧口令应被拒绝。
5. **回滚**：停 Neo4j → 用第 1 步的 `auth.bak-before-rotate` 覆盖 `data/dbms/auth`
   （或再执行 `ALTER CURRENT USER SET PASSWORD` 改回旧值）→ 恢复 `config.local.json`
   旧口令 → 重启 Neo4j／后端 → 用第 4 步校验。若无法回滚口令，先用备份认证文件恢复，
   再排查应用配置。
6. **RBAC 的后续选项**（不在本会话执行）：网络隔离保持 `127.0.0.1`；为图谱单独实例；
   或升级 Enterprise 后按最小角色建模。Community 下不要尝试 `CREATE ROLE`。
