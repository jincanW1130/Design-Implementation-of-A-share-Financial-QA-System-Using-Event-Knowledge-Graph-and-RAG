## 三、配置分层

### 3.1 读取顺序

```
config.local.json
  → config.<env>.local.json（存在才叠加；env 由 ASHARE_ENV 决定，缺省 dev）
  → ASHARE_* 环境变量（最高优先级）
```

- `ASHARE_CONFIG_FILE` 可指定另一份基础 JSON（相对路径按后端目录解析）；
- 不设任何 `ASHARE_*` 时，行为与分层前逐项一致。

### 3.2 可覆盖键

`mysql_host`、`mysql_port`、`mysql_user`、`mysql_password`、`mysql_database`、`mysql_charset`、
`neo4j_uri`、`neo4j_user`、`neo4j_password`、`backend_port`、`frontend_port`、`log_path`、
`admin_token`、`trust_proxy_headers`、`qa_runs_retention_days`。

环境变量名为 `ASHARE_` + 键名大写，例如 `ASHARE_MYSQL_PASSWORD`。

### 3.3 配置模板与凭据纪律

```bat
copy 交付物\03-代码\后端\config.local.json.example 交付物\03-代码\后端\config.local.json
```

- `config.local.json` 被 `.gitignore` 覆盖，**不入库**；
- 口令、`admin_token`、模型密钥**不写死、不回显、不进日志、不进前端构建产物**；
- `admin_token` 留空 = 管理接口 fail closed（全部 401/4001）；
- `trust_proxy_headers` 默认 `false`；只有确认在可信反向代理后才设 `true`；
- `log_path` 留空 = 只出 stderr；建议在长期运行时配置轮转日志。

### 3.4 容器配置

- `config.docker.json` 是容器模板，挂载为容器内 `config.local.json`；
- 容器网络中的主机名：MySQL=`mysql`、Neo4j=`neo4j`（Compose 形态）；
- 口令来自 `.env`（模板 `.env.example`），不写进清单。

## 四、本机部署步骤

### 4.1 一键启动（推荐）

```powershell
powershell -ExecutionPolicy Bypass -File 交付物\10-部署\启动.ps1
# 只起后端
powershell -ExecutionPolicy Bypass -File 交付物\10-部署\启动.ps1 -NoFrontend
# 保持 WSL 常驻（Neo4j 不被空闲挂起）
powershell -ExecutionPolicy Bypass -File 交付物\10-部署\启动.ps1 -KeepAlive
# 停止
powershell -ExecutionPolicy Bypass -File 交付物\10-部署\启动.ps1 -Stop
```

脚本依次做：MySQL 检查 → Neo4j 启动 → 后端启动 → 前端启动 → 健康检查，每步打印实测结果。

### 4.2 手动启动

**① MySQL**

```bat
sc query MySQL84
:: 未运行则：net start MySQL84（需管理员）
```

确认库与表：

```bat
mysql -u root -p -e "SHOW DATABASES LIKE 'ashare_qa';"
```

**② Neo4j（WSL2）**

```bat
wsl -d Ubuntu -u root -- bash -lc "systemctl start docker; docker start ashare-neo4j"
```

> **必须保活**：WSL2 空闲约 10～15 秒会挂起，Neo4j 随之不可达。长期运行请用
> `启动.ps1 -KeepAlive`，或另开窗口执行 `wsl -d Ubuntu -u root -- tail -f /dev/null`。
> **不要执行 `wsl --shutdown`**（会停掉 Neo4j；本项目约束明确禁止）。

**③ 后端**

```bat
cd 交付物\03-代码\后端
python run.py
```

**④ 前端**

```bat
cd 交付物\03-代码\前端
npm run dev
```

### 4.3 首次数据准备

1. 建库建表：执行 `交付物/03-代码/后端/schema/六张表.sql`（或 Compose 首次启动自动执行）；
2. 导入数据：`python 交付物\03-代码\后端\tools\import_data.py`；
3. 向量索引：按 `交付物/03-代码/数据准备/embed.py` 的既有流程构建；
4. 图谱导出：确认 `交付物/04-数据与知识图谱/事件抽取与知识图谱/图谱导出/v2.1_v1_3/`
   下 `nodes.csv`、`edges.csv` 存在；
5. 一致性检查：`GET /api/admin/consistency-check`（需 `X-Admin-Token`）。

### 4.4 启动自检

```bat
python 工具\启动自检.py
```

- 只读检查配置、输入、索引、模型、MySQL、Neo4j、端口、日志；
- 全 OK/WARN 退出 0，任一 FAIL 退出 1；
- 第 4 轮实测：27 OK / 2 WARN / 0 FAIL。

## 五、容器形态

### 5.1 后端镜像

```bash
# 在 WSL2 Ubuntu 内
cd /mnt/c/Users/15129/Desktop/毕业设计
docker build -f 交付物/10-部署/Dockerfile -t ashare-qa-backend:local .
docker run --rm -d --name ashare-qa-api --network host \
  -v "$PWD/交付物/10-部署/config.docker.json:/app/交付物/03-代码/后端/config.local.json:ro" \
  -v /mnt/d/Cache/huggingface:/app/hf:ro \
  ashare-qa-backend:local
curl -s http://127.0.0.1:8000/api/health
```

- 镜像基于 Python 3.12-slim，安装 `requirements.txt` 全部依赖；
- 镜像包含后端、检索、问答三个组件与只读数据索引/图谱导出物；
- `.dockerignore` 排除 `node_modules/`、`dist/`、`_工作底稿/`、`config.local.json`；
- embedding 模型不打进镜像，**必须挂载 HF 缓存**，否则向量检索报 3003。

### 5.2 Compose（未在本机实际拉起）

```bash
cd 交付物/10-部署
cp .env.example .env          # 填 MYSQL_ROOT_PASSWORD / NEO4J_PASSWORD / HF_CACHE_DIR
docker compose up -d --build
docker compose exec -T backend python 交付物/03-代码/后端/tools/import_data.py
curl -s http://127.0.0.1:8000/api/health
```

**已知限制**：

1. 本机 WSL2 的 `docker.io` 包不带 compose 插件（`docker compose` → `unknown command`），
   Compose 清单只做了 YAML 语法与结构校验，**未实际拉起**；
2. 容器连不到宿主 MySQL：Windows MySQL 只监听 `127.0.0.1`，需管理员改 `bind-address` 或另起
   `mysql:8.4` 容器；
3. 未安装 Docker Desktop（本机账户非管理员），Docker 仅以 WSL2 Docker Engine 形态可用；
4. 不引入 K8s/多机编排。

### 5.3 前端容器

`Dockerfile.frontend` 多阶段构建（Node 构建 → Nginx 静态托管），`nginx.conf` 将 `/api/` 反代到
`backend:8000`，并生成/透传 `X-Request-Id`；`client_max_body_size 64k` 与后端请求体上限对齐；
问答代理读超时 320 s。

## 八、排错清单

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| `/api/health` mysql=false | MySQL 服务未启动/口令错/库不存在 | 检查服务、`config.local.json`、库名 |
| neo4j=false，十几秒后掉线 | WSL2 空闲挂起 | 用 `-KeepAlive` 或常驻 WSL 会话；**不要 `wsl --shutdown`** 后忘记重启 |
| vector_index=false | 索引文件缺失/模型快照未挂载 | 检查索引与 HF 缓存；容器挂载 `/app/hf` |
| model_config=false | 模型密钥缺失/端点不可达 | 检查 `LLM_API_KEY` 或配置；不要打印密钥 |
| 问答 3001 | Neo4j 不可达 | `docker start ashare-neo4j`；检查 bolt 7687 |
| 问答 3002 | 模型超时 | 检查网络/端点；重试 |
| 问答 3003 | 向量索引/记录缺失 | 重建索引；检查 `build_meta.json` |
| 大面积 429/1004 | 限流 | 降低并发；压测时临时放宽 `ASHARE_RATE_LIMIT_MAX`，**结束恢复默认** |
| 管理接口全部 401/4001 | `admin_token` 未配置/请求头缺失 | 配置令牌并重启；请求带 `X-Admin-Token` |
| 启动脚本卡住 | WSL 偶发 `E_UNEXPECTED` | 重启 WSL 服务（**不是 `wsl --shutdown` 作为常规手段**）；重跑脚本 |
| 前端 5173 打不开 | dev server 未启动/端口占用 | `npm run dev`；检查端口 |
| 构建失败 | Node 版本/依赖 | `npm ci`；确认 Node 24.x |

## 九、安全注意事项

1. 凭据只走 `config.local.json` 或环境变量；不写进代码、文档、截图、提交信息；
2. 管理面令牌通过 `X-Admin-Token` 传递，生产环境应走 HTTPS/内网；
3. `trust_proxy_headers` 默认关闭，避免伪造 `X-Forwarded-For` 绕过限流；
4. 限流是单进程滑动窗口，多实例不共享；横向扩容需在网关层补全局限流；
5. `/api/health` 豁免限流，仅用于探活，不暴露敏感配置；
6. 日志中不出现问题原文、Prompt、密钥；错误 `detail` 只进日志。
