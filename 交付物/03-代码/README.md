# 代码

本项目**实现代码的唯一工作区**。第 5～10 阶段共用这一个目录。

## 一、为什么按组件分，而不按阶段分

工作区里的文档按阶段分目录（`阶段01-…`～`阶段05-…`），因为文档是**一次性的产出**；代码不这样分，因为数据管线的切分器、抽取器、检索器、后端接口最终要长成**同一个可运行系统**，按阶段切开会在集成时产生重复实现与版本分叉。这里按**组件**组织，阶段只决定"什么时候开始写哪个组件"。

## 三、编写纪律

1. **技术栈不得越界**：Vue 3 ＋ FastAPI ＋ MySQL ＋ Neo4j ＋ FAISS ＋ 大模型 API ＋ Docker。《02》第8.4节 明确不引入的技术（LangChain、LlamaIndex、独立向量数据库、Elasticsearch、Kafka、微服务、K8s、Agent 自主编排、多模态与语音、实时行情）一律不得出现在依赖里。
2. **FAISS 的表述**：代码、注释与文档一律写"向量索引"或"向量检索组件"，不写"向量数据库"。
3. **口径以《02》为准**：分层职责、模块边界、六张表、本体 6／8／9、四种时间、Top-K 五步契约、Method＝C 组，都按《02》与《10》实现，不得在代码里另立一套。
4. **接口以《10》第4.7节 为准**：路径、请求字段、响应字段、错误码照接口清单实现；实现阶段如需微调，须回到《10》登记，避免文档与实现脱节。
5. **密钥不进仓库、不进前端**：模型 API Key 等一律走环境变量或本地配置文件，并把配置文件名写进 `.gitignore`。
6. **数据不可变**：数据集按版本目录固化（`交付物/04-数据与知识图谱/数据准备\数据集\v1.1\`），版本内的文件不再修改；扩充规模一律新建 `v1.1`／`v2.0` 目录。
7. **脚本可重复执行**：采集与处理脚本必须幂等——同一输入重复运行不产生重复记录，中断后可以从中间步骤续跑。
