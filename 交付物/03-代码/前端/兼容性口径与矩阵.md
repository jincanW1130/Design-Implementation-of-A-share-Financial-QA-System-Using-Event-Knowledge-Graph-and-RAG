# 前端兼容性口径与浏览器矩阵

> 建立于 2026-10-11，对应审查报告（第一轮判「兼容性：不通过——零整改：矩阵/build.target/口径三缺」）
> 与第二轮复评（维持不通过）。本文件补齐三缺：**build.target 显式声明**（`vite.config.js`
> 的 `build.target: 'es2020'`）、**浏览器矩阵**、**支持口径声明**。

## 一、支持口径声明

* **构建目标**：`es2020`（`vite.config.js` 显式声明，取代 Vite 默认 `modules`——默认值随
  Vite 版本漂移、不可作为口径）。
* **支持范围**：2020 年起的 **evergreen 浏览器**——Chrome 80+／Edge 80+／Firefox 75+／
  Safari 13.1+（含移动端 iOS Safari 13.4+／Chrome Android 80+）。
* **明确不支持**：**IE 全系**（项目无 IE 业务需求，未做任何 IE 适配）；**ES2020 之前的
  常青浏览器旧版本**（不注入 polyfill——本系统是内网演示与毕设演示形态，不承担旧浏览器
  兼容义务；需要时在 `vite.config.js` 加 `@vitejs/plugin-legacy` 并重新登记口径）。
* **分辨率**：桌面优先（1440×900 基准）；768px 以下未做移动端适配（如实登记为不支持）。

## 三、技术依据

* 源码语法面：可选链（`?.`）／空值合并（`??`）为 ES2020 特性，`esbuild` 按 `es2020`
  目标转译，语法兼容性由构建保证；
* 运行时 API 使用面：`fetch`／`URLSearchParams`／`ResizeObserver`（图谱画布）——
  均为 Chrome 80+／Safari 13.1+ 基线内 API，未使用实验性 API；
* `backdrop-filter` 等视觉特性缺 `-webkit-` 前缀时降级为无毛玻璃效果（可用性第一轮已
  登记 L 级，不影响功能）。

## 四、登记纪律

构建目标变更（`vite.config.js` 的 `build.target`）**必须**同步更新本文件第一节与矩阵；
手工格补测后在「状态」列登记日期与结论（通过／发现缺陷单号）。
