### 1.5 一次提问的调用链（`POST /api/qa/ask`）

1. 前端 `AskView.submit()` 校验非空、≤500 字、无控制字符，生成 `session_id`，经
   `api.js.askQuestion()` 发出可取消请求（320 s 超时）。
2. FastAPI 中间件分配/透传 `X-Request-Id`，检查请求体上限与限流。
3. `api/qa.py::ask`：缺 `question` → 1003；空/超长 → 1001；缺 `session_id` → 1003；
   出现分组或未登记字段 → 1002；固定使用 `config.DEFAULT_GROUP`（C 组）。
4. `services/qa_service.py::ask`（工作线程）：
   - 先按 `(session_id, question_text)` 查是否可复用；命中则直接返回 `reused=true`；
   - 否则在 `qa_runs/ask_<group>_<随机>` 下以子进程运行
     `问答/run_answer.py --question … --group C --now … --session-id … --out-dir …`；
   - 读取 `qa_records.jsonl` 与 `answer_trace.jsonl`；引用越界类失败按空结果处理（HTTP 200，不落库）；
   - 分配整数 ID（`GREATEST(MAX(question_id), MAX(answer_id)) + 1`），在同一事务写
     `question → answer → answer_evidence`（证据先删后插）；
   - 记录耗时分解日志：`backend_wait`、`llm_calls`、`llm_seconds`、`graph_used`、`evidence`。
5. 返回 `errors.ok(data)`：`{data: {...}, meta: {dataset_version, data_cutoff_time}}`。

## 2. MySQL 六张表（实测）

库：`ashare_qa`，字符集 `utf8mb4`，排序规则 `utf8mb4_0900_ai_ci`，InnoDB。
行数（2026-10-18 只读统计）：`user=0`、`document=709`、`document_chunk=5018`、
`question=30`、`answer=30`、`answer_evidence=293`。

### 2.1 表结构

| 表 | 主键 | 主要字段 | 外键 | 删除规则 |
| --- | --- | --- | --- | --- |
| `user` | `user_id BIGINT` | `username VARCHAR(64) UNIQUE`、`password_hash`、`create_time` | — | — |
| `document` | `doc_id BIGINT` | `title(512)`、`content LONGTEXT`、`source`、`url(1024)`、`publish_time`、`ingest_time`、`category`、`company_list(512)`、`create_time` | — | — |
| `document_chunk` | `chunk_id BIGINT` | `doc_id`、`chunk_index`、`content TEXT`、`token_count`、`vector_id` | `doc_id → document.doc_id` | `ON DELETE CASCADE` |
| `question` | `question_id BIGINT` | `user_id`、`session_id CHAR(36)`、`question_text TEXT`、`task_type(16)`、`gold_hop_depth`、`time_constraint`、`ask_time` | `user_id → user.user_id` | `ON DELETE SET NULL` |
| `answer` | `answer_id BIGINT` | `question_id`、`answer_text LONGTEXT`、`graph_path JSON`、`model_name(128)`、`prompt_version(16)`、`is_graph_extended`、`create_time` | `question_id → question.question_id` | `ON DELETE CASCADE` |
| `answer_evidence` | 复合主键 `(answer_id, chunk_id)` | `doc_id`、`rank`、`evidence_type(32)` | `answer_id → answer`、`chunk_id → document_chunk`、`doc_id → document` | 对 `answer` 级联；对 `chunk`/`document` 为 `RESTRICT` |

所有外键的 `UPDATE_RULE` 均为 `RESTRICT`。`answer_evidence` 对切块与文档采用 `RESTRICT`，
其目的是**保护历史回答的可追溯性**：被引用过的切块/文档不能直接删除（接口层对应 2003）。

### 2.2 索引（实测，含主键；共 24 条索引记录）

| 表 | 索引 | 类型 | 列 |
| --- | --- | --- | --- |
| `user` | `PRIMARY` | 唯一 | `user_id` |
| `user` | `uk_user_username` | 唯一 | `username` |
| `document` | `PRIMARY` / `idx_doc_publish_time` / `idx_doc_ingest_time` / `idx_doc_category` | 唯一 / 普通 ×3 | `doc_id` / `publish_time` / `ingest_time` / `category` |
| `document_chunk` | `PRIMARY` / `uk_chunk_doc_index` / `uk_chunk_vector_id` / `idx_chunk_doc_id` | 唯一 / 唯一 / 唯一 / 普通 | `chunk_id` / `(doc_id, chunk_index)` / `vector_id` / `doc_id` |
| `question` | `PRIMARY` / `idx_q_session_time` / `idx_q_task_type` / `idx_q_gold_hop_depth` / `idx_q_time_constraint` / `fk_question_user` | 唯一 / 普通 ×5 | `question_id` / `(session_id, ask_time)` / `task_type` / `gold_hop_depth` / `time_constraint` / `user_id` |
| `answer` | `PRIMARY` / `idx_a_question_id` / `idx_a_create_time` | 唯一 / 普通 ×2 | `answer_id` / `question_id` / `create_time` |
| `answer_evidence` | `PRIMARY` / `idx_ae_answer_id` / `idx_ae_doc_id` / `idx_ae_evidence_type` / `fk_ae_chunk` | 复合唯一 / 普通 ×4 | `(answer_id, chunk_id)` / `answer_id` / `doc_id` / `evidence_type` / `chunk_id` |

> `fk_ae_chunk`、`fk_question_user` 是 MySQL 为外键自动创建的支持索引；其余为
> `schema/六张表.sql` 中显式命名的索引（16 个命名普通/唯一索引，外加 6 个主键）。

### 2.3 口径

- `question_id` / `answer_id` 为 BIGINT，但第 8 阶段题集用 `Q-001` / `A-001` 字符串；
  接口层按 `MAX+1` 分配整数 ID，保证已导入的 1–30 号记录永不被覆盖。
- `is_graph_extended` 取 0/1；对应答案中是否含真实图谱路径段。
- `graph_path` 为 JSON 文本列，保存图谱路径原始载荷，不在数据库层解析。
- 本轮开始前基线：`question=30`、`answer=30`、`answer_evidence=293`；任何联调写入后
  用 `DELETE FROM ... WHERE question_id>30` 清理（本轮未产生残留）。

## 3. Neo4j 图谱（实测）

实例：Neo4j 5.26.31 Community Edition，`bolt://127.0.0.1:7687`。
规模：**3607 个节点 / 3614 条关系**。

### 3.1 节点标签与属性

| 标签 | 节点数 | 实存属性 |
| --- | --- | --- |
| `Event` | 1098 | `node_id`、`event_id`、`event_name`、`event_type`、`event_time`、`description`、`confidence`、`name` |
| `Company` | 938 | `node_id`、`company_name`、`stock_code`、`short_name`、`exchange`、`aliases`、`name` |
| `Document` | 692 | `node_id`、`doc_id`、`title`、`name`、`source`、`category`、`publish_time`、`url` |
| `Person` | 396 | `node_id`、`person_id`、`person_name`、`name` |
| `Institution` | 308 | `node_id`、`institution_id`、`institution_name`、`name` |

（`stock_code`、`event_id`、`doc_id` 等）是属性，不是唯一约束。`name` 为统一检索属性。

### 3.4 与设计文档 4.5.3 的已知差异

## 4. OpenAPI 使用说明（13.5）

### 4.1 入口

- 交互文档：<http://127.0.0.1:8000/docs>
- 机器可读：<http://127.0.0.1:8000/openapi.json>
- 实测：OpenAPI **3.1.0**，**30 条路径 / 33 个操作**（含 `HEAD /api/health`）；
  `components.schemas` 只有 2 个（`HTTPValidationError`、`ValidationError`），
  错误响应体使用**内联 schema**，不额外生成组件。
- 契约快照：`python 工具\契约快照.py`（与 `交付物/03-代码/后端/_契约快照.json` 比对）。

### 4.2 鉴权

- 普通只读接口与 `/api/qa/ask` 不需要令牌。
- `/api/admin/*` 全部需要请求头：

```http
X-Admin-Token: <config.local.json 的 admin_token>
```

- 未携带/不匹配 → HTTP 401 + code `4001`；未配置 `admin_token` 时 fail closed（同样 4001）。
- 前端普通用户通道（`X-Client-Role: user`，或 `Origin` / `Referer` 命中 CORS 白名单）
  访问后台 → HTTP 403 + code `4002`。
- OpenAPI 已声明 API Key 安全方案 `AdminToken`（第三轮补充），在 `/docs` 右上角
  **Authorize** 中填入令牌即可调试后台接口。

### 4.3 成功响应与分页

成功统一为：

```json
{
  "data": { "...": "..." },
  "meta": {
    "dataset_version": "v2.1",
    "data_cutoff_time": "2026-09-25T23:59:59+08:00"
  }
}
```

分页接口返回 `data = {total, items, page, page_size}`；默认 `page_size=20`，
上限 200；`page` 上限 100000（`config.API_LIMITS`）。

### 4.4 错误响应（真实探测，2026-10-18）

统一错误体只有两个键：

```json
{"code": 1001, "message": "输入为空或长度超出限制"}
```

每个响应同时带 `X-Request-Id`（如 `f33a0d233f5545d6`），便于把用户反馈与后端日志对齐；
`detail` 只写日志，不进响应体。

| HTTP | code | 触发示例（实测） | 响应体 |
| --- | --- | --- | --- |
| 400 | 1001 | `POST /api/qa/ask`，`question=""` | `{"code":1001,"message":"输入为空或长度超出限制"}` |
| 400 | 1002 | `POST /api/qa/ask`，请求体带 `"group":"A"` | `{"code":1002,"message":"参数格式错误"}` |
| 400 | 1003 | `POST /api/qa/ask`，缺 `question` | `{"code":1003,"message":"必填字段缺失"}` |
| 404 | 2001 | `GET /api/qa/answers/99999999` | `{"code":2001,"message":"资源不存在"}` |
| 200 | 2002 | `GET /api/history?session_id=不存在` | `{"data":{"total":0,"items":[],"page":1,"page_size":20},"meta":{...}}` |
| 405 | 1005 | `DELETE /api/health` | `{"code":1005,"message":"请求方法不允许"}` |
| 401 | 4001 | `GET /api/admin/consistency-check`，无令牌 | `{"code":4001,"message":"凭据无效"}` |
| 403 | 4002 | 同上，带 `Origin: http://127.0.0.1:5173` | `{"code":4002,"message":"无操作权限"}` |

说明：

- **2002 是正常业务状态**：查询为空返回 HTTP 200，不是 4xx/5xx；前端显示中立提示。
- 3001（图谱不可用）、3002（模型超时）、3003（向量索引不可用）、3004（装配账目守卫未通过）、
  1004（限流）、2003（文档被历史引用）、9999（未捕获异常）为运行期错误码；本轮未人为触发
  3001/3002/3003/3004/9999，表中不编造样例。其 message 与 HTTP 状态以 `errors.CODES` 为准。
- 1004 由限流中间件返回 HTTP 429；当前默认 60 次/60 s（`ASHARE_RATE_LIMIT_MAX` 可覆盖）。

## 5. 核心算法注释索引

以下按「入口函数 → 不变量」列出，代码内已有对应注释；此处给出阅读顺序与机检口径。

### 5.1 切块 `数据准备/chunk.py`

- 入口：`chunk_document(content, params)`（约第 141 行）。
- 参数（`config.CHUNK`）：目标 400 字、最大 512 字、最小 128 字、重叠 50 字；
  边界优先级 `\n\n > \n > 。！？；… > .!?;`。
- 做法：在目标窗口内优先找高优先级边界，找不到退到低优先级；重叠区从上一块尾部取
  50 字；`_skip_leading_blank` 跳过块首空白；`token_count` 由 BGE tokenizer 统计，
  tokenizer 不可用时按非空白字符数兜底。
- 不变量：块非空；块长不超过 `max_chars`（除非单句超长，见函数注释）；相邻块有重叠；
  输出 JSONL 原子替换、UTF-8 无 BOM。

### 5.2 向量召回 `检索/vector_search.py`

- 入口：`VectorSearcher.search(question, n)`（约第 334 行）。
- 模型：`BAAI/bge-small-zh-v1.5`，本地快照，512 维；索引 `IndexFlatIP`（向量已归一化，
  内积等价余弦）。
- 不变量：候选固定五键、键序固定（`FIELD_ORDER`）；`N=20`；sim 为 float；
  返回 `encode_seconds` / `search_seconds` 两个耗时项。
- 实测池：5018 条向量，维度 512。

### 5.3 BM25 / 字符 n-gram `增强/lexical_search.py`

- 入口：`tokenize(text, ngram_min=1, ngram_max=3)`、`LexicalIndex.build/search`、
  `rrf_fuse(rankings, k_rrf=60)`。
- 做法：中文按 1–3 字符 n-gram 切分，英文/数字保留原词；倒排表用
  `array('I')` 存 `(文档下标 << 10) | tf`；BM25 的 `k1=1.5`、`b=0.75`。
- RRF：对多路排名按 `1/(k_rrf + rank)` 累加，`k_rrf=60`；只用于离线对照，**当前默认链路
  不启用**（见 `工具/实验_BM25离线对照.py` 的结论）。

### 5.4 可插拔 Rerank `增强/reranker.py`

- 入口：`rerank_records(records, question, reranker=None)`、`RerankedRunner`。
- 默认 `None`：原样返回同一对象，不改变候选集、顺序与字段。
- 自定义 reranker：必须返回原集合的**排列**；`_check_permutation` 校验长度、元素身份与
  重复，不合法即抛错，绝不静默兜底。
- 只重排、不增删：`rerank_result` 保持结果信封的其余字段不变。

### 5.5 图谱候选与预算 `检索/pipeline.py`

- 入口：`run_question(...)`（约第 1216 行）。
- 组 C：`graph_depth=2`，`time_filter=False`，`evidence_sort=False`。
- 预算：`N=20` 候选 → 证据优先级排序 → 在 `context_token_budget=3600` 内取
  `Top-K=10`，`graph_retention_share=2` 控制图谱层保留比例。
- 不变量：最终证据顺序固定；路径/事件三元组计入预算但不计入 K；时间过滤禁用时
  不按时间丢弃候选。

### 5.6 装配账目守卫 `问答/assemble.py`

- 入口：`assemble_case(...)`（约第 133 行）。
- **现场重算**：`text_tokens = Σ(每条 evidence.token_count)`；再合成
  `total = text + path_tokens + event_triple_tokens`，断言其等于上游 trace 的
  `total_tokens`——不一致直接 `SystemExit`，不静默按任一值继续。
- 其他自检：证据数 ≤ K；证据顺序必须等于 `final_evidence_chunk_ids`；总 token 不得超
  3600；trace 的 K/N 必须等于配置的 10/20；图谱载荷原样透传；语料查找必须成功。
- 返回 `checks` 六项，供上游汇总。

### 5.7 答案机检门禁 `问答/answer.py::gate`

11 个失败项（全部通过 `passed` 才为真）：

1. `citation_out_of_range`：引用编号超出证据条数；
2. `citation_missing`：正文没有任何 `[证据n]`；
3. `date_unverifiable`：答案全文出现无法回溯到证据/数据截止时间的日期；
4. `graph_section`：图谱段与 `graph_used` 不一致（有图谱却写“无”，或反之）；
5. `body_graph_marker_leak`：模型正文泄漏“无图谱”系统标记；
6. `body_section_header_leak`：模型正文泄漏系统段小标题；
7. `forbidden_terms`：命中禁词表；
8. `evidence_backlink`：证据回链不完整；
9. `empty_answer`：回答正文为空；
10. `time_note`：数据截至/判定区间段缺失或不匹配；
11. `open_ended_marker`：开放式题缺少固定分析标注（无开放式题时记不适用并通过）。

作用域：引用/泄漏类只看模型正文；日期与禁词看答案全文；开放式标注按题集
`task_type` 判定，不靠关键词猜。

## 7. 已知限制与边界

- 后端为**单进程**；MySQL 单连接在 `_DB_LOCK` 内串行化，多 worker 需先改连接池。
- 进程内缓存与指标均**非跨进程**；重启即清零。
- BM25/RRF/Rerank 为可插拔/离线组件，默认链路仍是“向量 + 图谱”；
  HNSW 为实验性对比，`IndexFlatIP` 仍是默认。
- Neo4j Community Edition 无细粒度 RBAC；最小权限依赖独立账号 + 网络绑定 + 防火墙。
- 设计文档 4.5.3 与实测图谱元数据存在第 3.4 节所列差异；本轮未改已定稿文档、未重建图谱。
