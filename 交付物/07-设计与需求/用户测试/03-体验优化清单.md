## 一、O1　请求预算：75 次 → 34 次（后端窗口 60 次／60 秒）

### 实测事实

- 一次完整走查（首屏 → 提问页 → 图谱页 → 搜两次 → 历史页 → 回看）发出 **75 次** `/api/*`，**超窗口 15 次**，实测 **19 条 429**；
- 重复集中在**同一份不可变只读数据**：图谱页搜一次实体，把 `/graph/entities/600519`、`/graph/entities/600519/evidence`、`/graph/entities/600519/neighbors`、`/graph/paths` 与 7 个 `EVT-*` 事件详情**又完整拉了一遍**（第 ④ 步 28 次），而这些在第 ③ 步刚拉过、载荷一模一样；
- 受影响端点里包含 `GET /api/qa/answers/45`、`GET /api/evidence/45`、`GET /api/evidence/45/graph-path`——**连「答案与证据」页本身都可能因限流打不开**。

### 改法（`src/api.js`）

| 机制 | 取值 | 说明 |
| --- | --- | --- |
| 缓存白名单 | 7 类只读端点：实体详情／邻居／实体证据／事件详情／`/graph/paths`／`documents/{doc}/chunks/{chunk}`／`evidence/{answer}/graph-path` | 全串锚定、按**不含 query** 的 path 判断 |
| 明确**不**缓存 | 实体搜索列表、事件列表、`/qa/ask`、`/qa/answers/*`、`/history*`、`/market/*`、`/config/meta`、`/health`、`/evidence/{answer}` | 搜索与列表必须打真实接口，否则会掩盖新数据 |
| TTL | **60 秒** | 与后端限流窗口同量级 |
| 容量 | **200 条**，LRU 淘汰（`Map` 插入序，取用时 `delete`+`set`） | 有界，不会无限涨 |
| 并发合并 | 同 URL 在途时复用同一个 Promise | 第 ③→④ 步的重复请求就发生在几秒内，光有缓存不够 |
| 失效 | 成功的 `POST /qa/ask` 整表清空；另导出 `clearApiCache()` 供调试／将来手动刷新 | 失败响应**绝不入缓存**；用「代际号」挡住清空后返回的在途响应 |
| 返回值 | 命中时给**顶层浅拷贝** | 已知边界：嵌套对象仍是共享引用，现有调用方均只读（**已如实登记**） |

### 自证

离线断言 15 条全过（同路径连续两次 `fetch=1`、并发同路径 `fetch=1`、失败不入缓存、非白名单两次 `fetch=2`、TTL 60 s 到期重取、成功的 ask 清缓存／失败的 ask 不清、容量 200 触发 LRU）。
真实浏览器两遍（冷／热）：**34 次、0 条 429**，逐步明细见 `04-复测对照与验收.md`。

## 二、O2　429 韧性：从「静默失败」到「可感知 ＋ 自动重试」

### 实测事实

`api.js` 早已把「，请约 N 秒后重试」拼进错误消息，但调用点 `catch { results = [] }`／`catch { gp = null }` 把整条错误丢掉——用户读到的是「（无结果）／未检索到／未接入」，方向性误读。

### 改法（`src/api.js` ＋ `src/App.vue`）

1. **一次性退避重试**：仅对「重试无副作用或额外成本」的请求，且**仅一次**；等待 `Retry-After`，**上限钳到 5 秒**，缺失时 1.5 秒；并发退避**共享同一个窗口**（不会 1 s＋1 s＋5 s 累加）；重试仍失败时抛出的 `ApiError` 与改前**逐字一致**（同 code、同「，请约 N 秒后重试」）。
2. **可重试判据的关键修正**（这是本轮唯一一处**放宽**）：`POST /api/qa/ask` 现在**也允许重试一次**。依据：429 是 `main.py` 的限流中间件在 `await call_next(request)` **之前**直接拒绝的（`main.py:182-194`），**被拒请求根本没进业务逻辑、没有触发任何模型调用**，重试不会重复扣费／重复落库；而**非限流**失败（超时 3002／模型侧错误）**仍然绝不重试**——那道闸由「`resp.status===429 || code===1004`」把住。
3. **限流可感知**：新增极小订阅接口 `throttleState()`／`onThrottleChange(fn)`（只含 `{active, retryAfterSeconds, message}`，**无后端地址、无密钥、无库名／模型名**），`App.vue` 在顶栏下方加一条横幅，文案逐字为：
   > 后端限流｜预计还需 N 秒：每分钟请求数已达上限，正在自动重试；**此期间的空白不代表数据不存在，不是数据缺失。**｜立即重试

### 自证

离线 15 条断言（含「`/qa/ask` 撞 429 只重试一次」「`Retry-After` 缺失→1.5 s」「给 30 s 被钳到 5 s」「并发共享窗口不叠加」「退避期间兄弟请求成功不清掉横幅」）；jsdom 挂载 App.vue 断言横幅渲染与「立即重试」可点。
**真实浏览器实证**：最终 UAT 里 `/qa/ask` 一次就成功、**主链路 429 从 20 条降到 0 条**；被限流时按钮上出现「立即重试」（T5 的 Tab 序列里取到过）。

## 三、O3　图谱页：空结果不留旧数据、搜索词留痕、失败与空结果分开

### 实测事实

搜不存在的实体 → 候选区「（无结果）」，但**主画布仍显示 600519 的 11 节点／11 边、属性面板仍「已选中 · 贵州茅台 600519」**；点选候选后输入框被清空、页面不留「我搜的是什么」；检索失败与空结果都退化成同一句「（无结果）」。

### 改法（`src/views/GraphView.vue`，只改这一个文件）

1. **空结果清画布**：新增 `clearCanvasForEmpty()`，走与 `renderGraph()` 同一条销毁路径（`G.destroy()` ＋ 容器清空 ＋ 时间轴月份重置 ＋ `anchor.value=''`），空态文案**逐字回显用户输入**，并给出可操作建议：「可改用 6 位股票代码（如 600519）或更短的公司简称重试。」
2. **搜索词留痕**：点选候选时写 `route.query` 的 `entity` ＋ `q`，搜索区常显「上次搜索 <词>」，**不再清空输入框**；先落 `anchor` 再改 URL，使 `watch(route.query.entity)` 不会触发第二次 `load`（实测该锚点 `/neighbors` **只请求 1 次**）。
3. **失败与空结果分开**：`catch` 里**不动画布**，单独出错误块并原样展示 `e.code` 与 `e.message`（含「请约 N 秒后重试」），文案明确写「是这次检索没成功，不是库里没有这家公司」。
4. **不再静默截断**：改用后端真正认的 `page`／`page_size`（原 `limit` 后端**根本不认**，实测被忽略成默认 20 条），按实返 `total` 报数：「共 16 个匹配，已显示前 8 个」，并加「显示更多」。
5. **候选可区分**：chip 补 `stock_code || node_id`，实测为「宁德时代 · Company · 300750」。

### 自证

Playwright 6 步断言全过：空态后 `.gnode` 计数 = 0、页面无任何「已选中」字样、URL 带 `entity`＋`q`、点选后仍显示「上次搜索 宁德时代」、限流时显示「错误码 1004」而不下沉成「未检索到」、扩容后 14 个候选全出。

## 七、O7　两个首页 CTA 的口径对齐（2026-10-17 作者拍板：A ＋ D）

### 实测事实

   **口径说明**：这不是造演示数据，而是**指向库里既有的真实记录**——屏②页脚「取自一次真实问答输出，原样呈现，未做改写」的声明对它同样成立；若该记录将来被清理，按钮会落到屏②的 2001「资源不存在」（如实报错，不伪造）。
2. **D（新建会话）**：`App.vue` 顶栏按钮文案改为**「去提问」**，并加 `title`：「回到提问页；本系统是单轮问答，不维护多会话列表，历史记录按浏览器会话隔离（FR-06）」。**没有隐藏任何行为、也没有新增假功能**，只是把承诺说准。
