### F1（必改·静默错误）`extract.py` 先落 `run_history` 再算并写复现性块

**改前**（`交付物/03-代码\抽取与图谱\extract.py` 原 L1285–1298）：`dump_json(OUT["verify"], …)` 写在
`append_run_history(stats)` 之前，所以本轮记录进不了自己的 `reproducibility`；本批产物表现为
`runs=2`、`documents=[3,709]`、`compared_runs=[2]`（只有一条）、`identical_across_runs=false`
——**根本没有发生比较**。

**改法**（现在 L1329–1336，位置见 `05_收口\改动行号定位.txt`）：

```python

    # 顺序硬约束：**先落本轮的 run_history 记录，再算并写复现性块**。
    # 历史缺陷（2026-09-27 审查 B 的缺陷 1）：verify.json 曾在 append_run_history 之前写出，
    # 于是 reproducibility 永远看不到本轮记录——单跑一轮时 runs=1，跑两轮时看到的是上一轮
    # 与更早一轮；本批的表现就是 runs=2、compared_runs=[2]（只有一条），在「根本没比较」
    # 的情况下返回 identical_across_runs=false。比较逻辑本身（reproducibility_check）不变。
    append_run_history(stats)
    dump_json(OUT["verify"],
              build_verify_payload(docs, chunks, records, rejects_all, selection))
```

比较逻辑 `reproducibility_check()` **一个字节未改**（仍按「末两次同文档规模的运行」取
`same_scope[-2:]` 比清单哈希），不存在「假装比较过」。

### F5（必改·时区不一致）统一固定 `+08:00`

扫描 3588 个文件、6553 个时间戳；UTC 偏移不是 +08:00 的 0 处

**证据二**：现行 v1.2 全部产物（`_全量\v2.1_v1_2\`、`图谱导出\v2.1_v1_2\`、

## ④ F8 逐条的「修／不修＋理由」

**已修（3 条＋时区）**：

1. `--docs` 绕开 pilot 选样断言——修的理由：它让「pilot 样本合规」这条硬门禁在带 `--docs` 时**静默失效**，
   属守卫失效而非能力问题；修法只把被跳过的断言**显式化**（打印＋`assertion_skipped`），
   不改变任何合法用法（`--docs` 子集运行本来就无法满足整份样本的构成断言）。
2. 丢弃样本 `or 0`——修的理由：会把「没有落点」写成 `doc_id=0/chunk_id=0` 的**假落点**，
   审计回原文必然查不到；修后缺失即 `null`，本批数据逐字节不变。
3. `_dropped_from_stats` 读不到按 0——修的理由：`--verify-only` 下这会把「本应丢弃 >0 条但统计读不到」
   的失败读成通过；修后「读不到」与「读到 0」分开，读不到按失败记账。
4. 时区——修的理由与方法见 §①-F5。

**不修（2 条，均为环境相关假红，任务书也点名「不宜现在改」）**：

5. **R1 依赖绝对路径**：`manifest_宽口径_最终.json` 的 `root` 是绝对路径，`验收第6阶段.py`
   用它把基线条目过滤到「当前 `config.DATASET_DIR`」。异地（复制工作区／CI）时没有条目命中，
   报的是「找不到基线，无法比对」——**假红**，且这条恰恰是「数据集只读」硬门禁，异地等于失效。
   不改的理由：任何「放宽匹配」的改法（忽略 root、只按相对路径匹配）都在**削弱一条硬门禁**，
   而它的正确修法是「基线文件改成相对路径 ＋ 版本化」，涉及第 5 阶段封版清单的数据格式，
   属跨阶段口径调整——应由作者裁定后再动（建议：把 `root` 改为「相对仓库根」的路径，
   或让 R1 同时接受「相对路径集合逐条一致」作为基线命中条件，并在《13》/《00》登记）。
   影响面：仅异地复现评估；本机与两个 profile 的现行 101/101 不受影响。
