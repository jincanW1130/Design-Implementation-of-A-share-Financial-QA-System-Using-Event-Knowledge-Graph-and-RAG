## 1. 选题契合度（维度①.1）

**判定：契合软件工程本科培养目标，属「系统设计与实现为主体 + 实证对比为辅」的合格选题，非纯算法研究。**

证据：

| 契合软件工程的要素 | 证据位置 |
| --- | --- |
| 题目含「系统设计与实现」，对象收窄为「智能问答系统」 | `01-项目总体方案（导师审阅版）.md:22`（题目收敛说明明确「按需求分析、系统设计、数据设计、模块实现、系统集成、测试与评价的主线展开」） |
| 明确系统功能六项（信息管理/事件抽取/知识图谱/智能问答/证据追溯/历史问答） | `01:46–53` |
| 完整需求工程：角色、功能需求、用例、非功能需求、可行性、**需求追溯矩阵** | `07-需求分析（第三阶段）.md`：§二 角色（`:92`）、§三 FR-01～06（`:149`）、§四 UC-01～07（`:349`）、§五 NFR-01～06（`:541`）、§六 可行性（`:597`）、§七 追溯矩阵（`:637`） |
| 论文骨架 7 章中 5 章为工程内容（第三章需求、第四章设计、第五章实现、第六章测试） | `02-项目执行总控文档.md:913–979` |
| 明确边界，主动排除「非软件工程」内容（不做股票预测/投资建议/量化交易） | `01:95–99`；`04-开题报告.md:316–352` |
| 技术栈是工程实现栈而非训练栈（FastAPI/MySQL/Neo4j/FAISS/Vue/Docker；不本地训练大模型） | `02:317–330`（§8.3） |

**需要点明的偏算法风险（不构成不契合，但答辩会被追问）**：
- 三个研究假设 H1–H3（`01:44`、`04:148–173`）是**对照实验命题**（KG-RAG vs Vector RAG、hop 深度、时间过滤），第六章 6.3/6.7/6.8/6.9（抽取/检索/问答/消融实验）本质是**实证研究**。选题的「学术性」主要由「实验对比」承载，而**新算法/新模型贡献偏弱**（系统未提出新模型，见 `01:109`「本文以『主要工作与特色』表述，不夸大创新程度」）。
- 结论：**选题契合，可在答辩中以「系统工程 + 可复现实验对比」定位**；建议正文强化「系统设计决策如何由需求推导」的工程闭环叙述，弱化「算法创新」暗示。
