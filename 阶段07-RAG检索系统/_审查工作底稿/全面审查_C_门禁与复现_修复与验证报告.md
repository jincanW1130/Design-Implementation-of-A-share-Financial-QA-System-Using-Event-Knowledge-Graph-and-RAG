## ① 换机必崩：`.gitattributes`

### 问题
仓库原有属性对 `*.md/*.py/*.html/*.csv/*.json` 钉了 `eol=lf`，但 `.cypher`／`.txt`／`.jsonl`／`.tsv` 未钉，落到 `* text=auto`。在 `text=auto` 下，检出时的换行由平台／`core.eol`／`core.autocrlf` 决定——Windows 上即 CRLF。于是**任何在 Windows 上的克隆**都会让 `图谱导出/v2.1_v1_2/replay.cypher` 变成 CRLF，而《验收第7阶段.py》把该文件的大小与 sha256 冻结成常量：

```
("replay_cypher", "阶段06-事件抽取与知识图谱/图谱导出/v2.1_v1_2/replay.cypher",
 727503, "8cdb68d0782b04a852614dbbfee51efe81885f059d957b2a96c9655746b6c9ae")
```

CRLF 版本是 733064 B / `75d338…`，与冻结值不符 ⇒ **阶段 07 的 C2／镜像指纹在任何 Windows 克隆上必红**。

### 改法（只增不减）
新增 6 行属性，未删除、未放宽任何既有行：

```gitattributes
*.cypher text eol=lf
*.jsonl  text eol=lf
*.txt    text eol=lf
*.tsv    text eol=lf
/.gitattributes text eol=lf
/.gitignore    text eol=lf
```

### 第 5 阶段（《C》第 6 项三处，M-13／M-14／M-15）

**问题 ①**：默认档（不加 `--with-idempotence`）下 N5a／N6／N7／N8 四项真实重跑检查**连占位都不打印**，汇总却写「99/99 项全部通过」——看不出有 4 项根本没跑。
**改法**：新增 `skip()`，把这 4 项显式打成 `[SKIP]` 并计入 `skips`；汇总行分别报「通过／失败／未执行」，收口结论在有未执行项时一并写明。

**问题 ②**：否定语境判定是**整行**含任一否定标记即豁免，而标记集里还有**裸**「无」「未」「非」——同一行任何位置的一个「无」能把该行所有出现一律放行。**改法**：两档收紧——强否定短语须与命中处**同行且距离 ≤18 字**；单个否定字（无／未／非）须**紧贴**在命中词**前面**（距离 0）。调用方自带 `neg_markers` 时仍按整行（那些是**状态标记**，如「保持 TBD」，并非对该词的否定）。

**问题 ③**：0 篇文档的数据集会在 J3 的 `min()` 上抛 `ValueError: min() iterable argument is empty` **直接崩掉**（一行报告都看不到）；且 I1–I4 在「0 篇／0 块」的退化循环上**一律判 `[OK ]`**。**改法**：新增 `Z0` 显式门禁（数据集为空即 FAIL），并把 I／J 两组的退化判据一并收口。
