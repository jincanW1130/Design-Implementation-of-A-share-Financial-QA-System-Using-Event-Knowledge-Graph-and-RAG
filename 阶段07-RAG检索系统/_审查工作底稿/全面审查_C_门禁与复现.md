### 2）门禁真伪抽验（对抗性，逐条见第三节）

在**临时副本**上对 5 个门禁各做 ≥3 处定点变异（"改前 exit/判据 → 改后 exit/判据"），结论：

- **有牙的**：第 4 阶段 6 项里 4 项真咬（六层顺序、图号连续、约束 5 的无豁免违规行、节标题内部改写）；第 5 阶段 3/3 真咬（E3 指纹、E1 url 唯一、C6 计数）；第 6 阶段 1/3 真咬（N2 条数）；跨文档核验 4/5 真咬（O2/O3、K 组悬空、O5 计数、F/G 组）。
- **没牙的（本次新发现，均为"假阴性"）**：
  1. **第 6 阶段完全不验"260 条槽位恒为 `pending_human_annotation` 且槽位为空"这条硬契约**——把 dev.jsonl 第 1 条的 `entities` 填成非空，门禁**照样 98/101、照样打印"人工标注尚未填写"的自我安慰证据行**。全库 grep：`annotation_emptiness` 在 `工具\` 下命中 **0 处**。该契约**另由 `工具\标注助手.py` 把守**（`status_pending_but_filled` 码，本次实证能咬），**但阶段验收脚本不把守**。
  2. **第 4 阶段"节标题逐字一致"是子串判据**：给 `### 4.7 接口设计` 追加后缀（`### 4.7 接口设计X`）**判过**；只有把标题**内部改写**才判错。
  3. **第 4 阶段"约束 5"是整行 `or` 启发式**：往文档里插一行"`本系统不按微服务方式组织；FAISS 被用作……（被禁术语）……承载检索。`"——**因为同一行里有"不按"两字，整行被当作"排除语境"放过**，FAIL 行还会固执地打印"均在排除语境"。
  4. **跨文档核验 M 组不双向**：在根目录新建 `阶段99-临时测试目录\`，门禁 exit 0，毫无反应。
- **附带发现（稳健性，非"抽验项"但同一批跑出来）**：`工具\验收第7阶段.py` 第 756 行 `del index` 是**无条件**语句。一旦 `faiss.index` 缺失（清洁室里就是如此），D1 走 `except` 分支、`index` 从未绑定，脚本在**第 9 项就抛 `NameError` 整体崩掉**，而不是"报 D1 失败、继续跑完"。

### 3）清洁室复现（逐条见第四节）

从**当前 HEAD（`3db59e9`）**导出干净副本（`git archive HEAD`，另做一次**真实 `git clone`** 交叉验证，两者结果完全一致）：

| 门禁 | clone 里的结果 | 能否离开 gitignored 数据独立复现 |
| --- | --- | --- |
| `工具\验收第4阶段文档.py` | **exit 0，76/76 全通过** | **能**（纯文档侧） |
| `工具\跨文档核验.py`（默认／`--strict-citations`） | exit 1，**2 项失败**（K 组 191 处悬空、O3 缺 22 份全文 PDF） | **部分**：判据都跑得动，但两处**判据的对象本身在 gitignore 里** |
| `阶段02-文献调研与开题\_替换执行\07_文档自检.py` | exit 1（C1／C2 全灭） | **否**（证据页与全文 PDF 均被 gitignore） |
| `工具\验收第5阶段数据.py` | exit 1，`缺少输入文件：…\阶段05-数据准备\数据集\v2.1`，**一项都没跑** | **否** |
| `工具\验收第6阶段.py` | exit 1，`FileNotFoundError` 崩溃，**检查项 0 项** | **否** |
| `工具\验收第7阶段.py` | exit 1，**第 9 项抛 `NameError: name 'index' is not defined` 崩溃** | **否** |

**结论：另一台机器 clone 本仓库后，门禁无法复现。** 唯一能跑通的是第 4 阶段文档门禁；数据侧三阶段（5／6／7）**连启动都做不到**。原因不是代码没提交，而是**被门禁当作验收对象的交付物本身被 `.gitignore` 排除了**：

- `阶段05-数据准备/数据集/`（含 v2.1 六个输入 **＋ 整个抽取评测集 dev/test/分层统计/标注工作区**）
- `阶段07-RAG检索系统/_工作底稿/`（第 7 阶段镜像链留痕）
- `阶段02-文献调研与开题/文献PDF/`、`_知网替换/证据/`、`_知网替换/*.pdf`（题录与正文锚定的证据）

**另有一条只能靠"clone 才知道"的硬伤**：`.gitattributes` 只给 `md／py／html／csv／json` 钉了 `eol=lf`，**`.cypher`／`.txt`／`.jsonl`／`.tsv` 没钉**。后果是——

- `阶段06-事件抽取与知识图谱/图谱导出/v2.1_v1_2/replay.cypher`：工作区 727 503 字节（LF，与门禁内写死的指纹 `8cdb68…` 一致），**clone 之后变成 733 064 字节、5561 个 CRLF、sha256 `75d338…`**。
- 所以 **第 7 阶段 C2 在任何 Windows clone 上都会 FAIL**，即使把数据集原样补齐也一样。
- 全量统计：**143 个已跟踪文件在 clone 中的字节与工作区不同**（CRLF 归一），其中就包括 `检索产出\*.jsonl`、`阶段02-文献调研与开题\_替换执行\22条题录指纹.json`（O1～O5 的黄金标准）。

**替代验证路径**：数据侧无法在 clone 上"跑",但可以"核"——门禁内写死的 **11 条冻结指纹**本身就是可脱离字节独立传递的**值级契约**。把数据集通过带外渠道（工程归档、私有盘）交付给复核者，复核者只需重算 11 个 sha256 与字节数即可完成"输入只读"的核对，**不需要**跑检索链。

### 2.4 `工具\核验知网题录.py`：保留还是删除？

**裁定：保留。** 理由（每条都可复核）：

1. **脚本内无任何凭据。** 对 `api_key／secret／token／cookie／password` 等形态扫描命中 **0 处**；它只读公开的知网空间检索页（`search.cnki.com.cn`），并把登录态域名放进 `BLOCKED_HOSTS`（`kns.`＋`cnki.net`、`pay.`＋`cnki.net`）**主动拒绝**。
2. **它已被门禁消费，不是孤岛。** 它的产物链（`_知网核验/知网题录.jsonl` → `_知网替换/22条题录指纹.json` → `跨文档核验.py` 的 **O1～O5**）正是 O 组的**黄金标准来源**。删脚本 = 删掉 O1～O5 的**可再生来源**，把一套"可再算"的判据退化成"写死的常数"。而 `22条题录指纹.json` **是已提交文件**（`git ls-files` 可查），删脚本后没人能解释它怎么来的。
3. **"登录路线作废"不等于"脚本作废"。** 站点在登录前就返回「安全验证」，账号路线确实走不通；但脚本现有的**公开页面路线**在 2026-09-28 跑通过（`运行日志.txt` 有记录，产出 `知网题录.jsonl` 与核验报告）。它现在的定位就是"**离线可复核的证据生成器 + 在线时的可选刷新器**"。
4. **公开仓 + 无凭据 + 只读公开页**，风险面可接受。

**若坚持要"清理在线抓取面"**，建议的**最小收口**（不是删）是：把脚本里**唯一发起网络请求的那一段**用一个显式开关（默认关闭，如 `--allow-network`）包起来，其余解析／指纹逻辑保留为纯离线函数。这样既满足"公开仓不发网络请求"的洁癖，又不丢 O1～O5 的再生能力。

**额外一条（不是"缺文件"，是"字节不一致"）**：**143 个已跟踪文件在 clone 中的字节与工作区不同**，全部是行尾归一造成的，其中包含门禁的比对对象：

- `阶段06-…\图谱导出\v2.1_v1_2\replay.cypher`：工作区 `727503` / LF；clone `733064` / 5561 个 CRLF / `sha256=75d338d39b45`——**与门禁内写死的 `8cdb68d0782b…` 不一致**。
- 11 输入逐条核对结果（`git archive` 与真实 clone **完全相同**）：`documents / chunks / faiss_index / vector_map / build_meta / dataset_meta` **MISSING**；`nodes_csv / edges_csv / graph_stats / human_confirmation` **字节一致**；`replay_cypher` **字节不一致（EOL）**。合计 **6 缺失 ＋ 1 字节不符 ＝ 7**，与门禁自己打印的"实际文件不一致 7 条"完全对上。

根因：`.gitattributes` 只钉了

```
* text=auto
*.md   text eol=lf
*.py   text eol=lf
*.html text eol=lf
*.csv  text eol=lf
*.json text eol=lf
```

**`.cypher`／`.txt`／`.jsonl`／`.tsv` 落到 `* text=auto` 上**，在 Windows 上按 `core.eol=native` 检出为 CRLF。

**最小修法（只增两行）**：在 `.gitattributes` 里补

```
*.cypher text eol=lf
*.jsonl  text eol=lf
*.txt    text eol=lf
*.tsv    text eol=lf
```

补完后，C2 在 clone 上就不会因为 `replay.cypher` 而 FAIL（当然数据集缺失仍会 FAIL——那是另一件事）。
