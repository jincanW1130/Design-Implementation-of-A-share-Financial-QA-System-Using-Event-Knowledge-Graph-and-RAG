### 3.1 编写口径与本体口径

本节的编号规则是：按《02》第6.2节 的功能顺序，一个模块一个编号，从 FR-01 起顺序编号，共六条。模块名称逐字照抄《02》第6.2节：**财经信息管理、财经事件抽取、事件知识图谱、智能问答、证据追溯、历史问答**。每个模块统一按"需求编号、使用者、功能描述、输入、处理、输出、前置条件、后置条件、边界与不做的事、来源追溯"十个字段展开。

财经事件抽取与事件知识图谱两个模块的对象定义照抄《02》第9.2节，不在本文件中改写、增减或合并。三类口径如下。

第一，实体类型为 6 类，标签与中文名称照抄《02》第9.2.1节。

| 实体类型（标签） | 中文名称 | 说明 |
| --- | --- | --- |
| Company | 公司 | 上市公司及在财经信息中出现的其他企业主体，是图谱的核心节点，以 stock_code 作为稳定业务唯一标识 |
| Person | 人物 | 公司高管、监管机构人员等与事件相关的人物 |
| Industry | 行业 | 公司所属行业以及事件涉及的行业 |
| Institution | 机构 | 监管机构、交易所、中介机构等 |
| Event | 事件 | 财经事件，本课题的核心知识单元 |
| Policy | 政策 | 与公司或行业相关的政策文件及其主题 |

Product（产品）与 Location（地点）列为可扩展类型，不进入第一版的本体、抽取规则与评测范围（《02》第9.2.1节）。

第二，核心事件类型固定为 8 种，逐条照抄《02》第9.2.2节：业绩事件、监管事件、股权事件、投资并购事件、重大合同事件、产品事件、政策事件、重大经营事件。第一版固定为以上 8 种核心事件类型，作为抽取、标注与评测唯一的 schema，不再保留浮动的事件类型数量表述（《02》第9.2.2节）。

第三，核心关系共 9 条，命名与属性照抄《02》第9.2.3节。

```text
(Company)-[:BELONGS_TO {valid_from, valid_to, source_doc_id, source_chunk_id, confidence}]->(Industry)
(Company)-[:SUPPLIES {source_doc_id, source_chunk_id, confidence}]->(Company)
(Company)-[:CUSTOMER_OF {source_doc_id, source_chunk_id, confidence}]->(Company)
(Company)-[:COMPETES_WITH {source_doc_id, source_chunk_id, confidence}]->(Company)
(Company)-[:HAS_EXECUTIVE {source_doc_id, source_chunk_id, confidence}]->(Person)
(Company | Person | Institution)-[:PARTICIPATES_IN {role, source_doc_id, source_chunk_id, confidence}]->(Event)   // role ∈ {主体, 合作方, 涉及方, 监管方, 受影响方}
(Event)-[:ISSUED_BY {source_doc_id, source_chunk_id, confidence}]->(Institution)                                 // 仅政策事件与监管事件
(Event)-[:RELATED_TO {source_doc_id, source_chunk_id, confidence}]->(Policy)
(Event)-[:EVIDENCED_BY]->(Document)                                                                              // 事件与其证据文档；本身即证据关系，不重复携带 source_doc_id
```

| 关系 | 方向 | 属性 | 说明 |
| --- | --- | --- | --- |
| BELONGS_TO | Company → Industry | valid_from、valid_to、source_doc_id、source_chunk_id、confidence | 公司所属行业，带有效时间区间，用于判断关系在查询时间点是否成立 |
| SUPPLIES | Company → Company | source_doc_id、source_chunk_id、confidence | 供应商关系，A 公司向 B 公司供货；方向按信息来源标注 |
| CUSTOMER_OF | Company → Company | source_doc_id、source_chunk_id、confidence | 客户关系，与供应商关系互为反向，按抽取结果确定方向 |
| COMPETES_WITH | Company → Company | source_doc_id、source_chunk_id、confidence | 竞争关系，第一版按抽取方向存一条 |
| HAS_EXECUTIVE | Company → Person | source_doc_id、source_chunk_id、confidence | 公司高管任职关系，必须带齐证据三项属性 |
| PARTICIPATES_IN | Company／Person／Institution → Event | role、source_doc_id、source_chunk_id、confidence | 公司、人物或机构参与事件，role ∈ {主体, 合作方, 涉及方, 监管方, 受影响方} |
| ISSUED_BY | Event → Institution | source_doc_id、source_chunk_id、confidence | 政策事件与监管事件中政策的发布机构或监管处罚的作出机构；其他事件类型不产生该关系 |
| RELATED_TO | Event → Policy | source_doc_id、source_chunk_id、confidence | 事件与相关政策之间的关联，必须带齐证据三项属性 |
| EVIDENCED_BY | Event → Document | 无 | 事件与其证据文档之间的关联，本身即证据关系，不再重复携带 source_doc_id；一个事件可以对应多份文档 |

关系的"命名与属性照抄"包含《02》第9.2.3节 表下的两条补充口径，必须一并沿用，否则图谱写入数量与统计口径会不一致。**第一条是去重规则**：同一机构既是政策或监管事件的发布／作出方、又参与该事件时，只写 ISSUED_BY，不再重复写 PARTICIPATES_IN——同一条事实写两份会让路径计数、事件参与主体统计与事件去重逻辑出现重复计算。**第二条是"监管方"role 的适用范围**：该 role 仅用于"参与事件但不是发布／作出方"的机构，发布／作出方一律用 ISSUED_BY 表达。此外，COMPETES_WITH 通常为对称关系，第一版按抽取方向存一条；若行业归属来自外部行业分类而非文本抽取，该分类文件同样作为一份 Document 入库并由 BELONGS_TO 的 source_doc_id 指向它，保证证据链不断（以上均见《02》第9.2.3节）。

证据属性口径统一为：**除 EVIDENCED_BY 外，其余 8 条核心语义关系统一携带 source_doc_id、source_chunk_id 与 confidence 三项证据属性**；三项证据属性是必需属性而不是可选补充，其中 BELONGS_TO 另带 valid_from、valid_to。这样处理之后，系统对任意一条事实都能回答"来自哪篇文档、哪个文本块、置信度多少"（《02》第9.2.3节）。

事件节点的核心属性为六项，照抄《02》第9.2.4节。

| 属性 | 含义 |
| --- | --- |
| event_id | 事件的唯一标识 |
| event_type | 事件类型，取值来自 8 种核心事件类型 |
| event_name | 事件名称 |
| event_time | 事件发生时间 |
| description | 事件描述，一句话说明事件经过 |
| confidence | 抽取置信度，0.0～1.0 之间的数值 |

除以上六项核心属性外，trigger（触发词）作为可选辅助字段保留，仅用于抽取调试与错误分析，不作为查询依据，也不进入检索与实验的判定逻辑（《02》第9.2.4节）。participants 与 publish_time 不作为事件属性：参与主体由 PARTICIPATES_IN 关系（含 role 属性）与 ISSUED_BY 关系表达，publish_time 与 source、url 一起归属 document。

时间维度的归属层级照抄《02》第10.1节：事件发生时间存放在 Event 节点的 event_time，文档发布时间存放在 Document 节点的 publish_time，关系有效时间以关系属性 valid_from、valid_to 表达，数据截止时间 data_cutoff_time 是数据集版本级属性，与 dataset_version 成对记录在数据集元信息中，不属于任何表（《02》第10.1节、第10.3节）。

- 功能描述：用户输入自然语言问题，例如"A 公司最近发生了哪些重大事件？"，系统依次完成问题分析、文本检索、图谱检索、时间过滤、证据排序与大模型生成，返回自然语言回答；问题中的"最近"按 event_time 判定（事件发生时间落在数据截止时间前 30 天以内），并以数据截止时间为基准解释（《02》第6.2节 功能 4）。
- 输入：用户提交的自然语言问题；会话标识 session_id（第一版用于历史记录归属）；数据集版本级属性 dataset_version 与 data_cutoff_time。
- 处理：
  1. 问题分析：判定问题类型与是否需要图谱扩展，识别问题中的实体与时间约束；
  2. 文本检索：用问题与实体关键词在向量索引中检索候选文本块；
  3. 图谱检索：按需要执行 0 跳（只进行文本检索）、1 跳（文本检索 ＋ 一跳图谱关系）或 2 跳（文本检索 ＋ 两跳图谱关系）扩展；
  4. 时间过滤：带时间约束的问题按 event_time 过滤事件节点，并沿关系做扩展；
  5. 证据排序：把向量检索结果与图谱检索结果合并排序；上下文超出预算时按固定裁剪规则裁剪，裁剪发生在证据排序之前，裁剪顺序为**先裁剪与问题实体无关的远端图谱路径，再依据向量检索的原始排名从后往前裁剪文本块**，且不使用证据排序的结果，以保证消融 D 组与 E 组得到完全相同的证据集合（《02》第12.4节、第12.6节）；候选证据不足 K 的题目在测试集构建阶段调整，不进入正式实验；**该约束只适用于测试集构建阶段**：题目一旦入库，不得因该题实验时的实际候选数少于 K 而将其排除，空缺位置记为未命中并按原指标定义计算（《02》第12.7节）；
  6. 大模型生成：基于证据生成自然语言回答，模型不得使用数据截止时间之后的信息，也不得在证据不足时用训练语料中的时间信息补全答案；
  7. 落库：question 记录问题与提问时间，answer 记录回答，answer_evidence 记录答案引用的证据。
- 输出：自然语言回答；本次问题所用相对时间的判定区间与数据截止时间说明；供证据追溯使用的证据集合；使用了图谱扩展时的图谱路径。
- 前置条件：文本已入库并完成向量索引构建与图谱写入；Embedding 模型与大语言模型接口可调用；问题非空且长度在接口限制之内；实验期间使用同一套固定的模型、参数与提示词配置（《02》第12.4节）。
- 后置条件：question、answer、answer_evidence 三条记录可关联还原本次问答；回答页面固定显示"数据截至：YYYY-MM-DD"；答案中注明所用判定区间（《02》第13节）。
- 边界与不做的事：不提供预测与投资决策类回答，边界清单见 8.2 节（《02》第5.1节、《04》第7.1节）；定量实验只使用可核验的事实型问题，开放式分析问题只用于 Demo 展示与案例分析、最多保留 1～2 例、必须在页面与答案中同屏标注"模型分析（非公开事实）"、不作为核心准确率依据、不参与图谱增强效果的判定、不计入任何指标（《02》第12.9节）；"最新／最近／近期"一律以 event_time 判定，不以 publish_time 判定，也不以系统运行当天为基准（《02》第10.3节）。

### 3.6 证据追溯（FR-05）

- 需求编号：FR-05
- 使用者：普通用户。
- 功能描述：答案下方展示回答来源、新闻来源、公告来源、相关事件，以及**使用了图谱扩展时**的图谱路径；**若本次回答未使用图谱扩展，则显式标注"本次回答未使用图谱扩展"**。用户可以从答案直接定位到具体文档、文本块与图谱关系，这是本系统的重点展示功能（《02》第6.2节 功能 5）。
- 输入：answer_evidence 记录（含文档编号与文本块编号）；文档元数据（来源类型、发布时间、文档编号、URL）；本次回答是否使用图谱扩展的标记；使用了图谱扩展时该次回答检索到的路径。
- 处理：
  1. 从 answer_evidence 取本次回答引用的全部证据，每条证据包含文档编号与文本块编号；
  2. 按来源类型分类展示：回答来源、新闻来源、公告来源与相关事件；
  3. 判断本次回答是否使用了图谱扩展；
  4. 使用了图谱扩展时展示图谱路径，路径上的每条关系回溯到 9 条核心关系之一，其中除 EVIDENCED_BY 外给出 source_doc_id、source_chunk_id 与 confidence，EVIDENCED_BY 的证据为其指向的 Document 节点；
  5. 未使用图谱扩展时，在该区域显式标注"本次回答未使用图谱扩展"，不留空，也不展示虚构路径；
  6. 提供从答案到原文的定位入口，展示来源类型、发布时间与文档编号。
- 输出：证据列表；图谱路径区域或其显式标注；可用于点击查看原文的定位信息。
- 前置条件：本次回答已生成；answer_evidence 已写入；若问题为开放式分析问题，页面已具备"模型分析（非公开事实）"的标注区域。
- 后置条件：每条证据均可定位到具体文档与文本块；证据列表中的记录均来自 answer_evidence 表；图谱路径中的每条关系均可回溯到《02》第9.2.3节 定义的 9 条核心关系之一（《02》第13节）。
- 边界与不做的事：0 跳问题（仅凭文本检索即可回答）以及未启用图谱扩展的实验组（Baseline 1、Baseline 2 与消融 A 组）客观上不存在图谱路径，**不得强行生成或展示虚构的图谱路径**（《02》第13节）；图谱关联只表示公开信息中出现的关联，不得表述为因果结论（《02》第5.3节）；本模块不新增证据类型，不引入独立于 answer_evidence 的证据来源。

### 3.7 历史问答（FR-06）

- 需求编号：FR-06
- 使用者：普通用户查看本会话历史；后台维护数据表。
- 功能描述：保存用户问题、提问时间、回答与引用证据，支持后续查看，同时为实验统计提供数据来源。第一版不启用登录时，历史记录按浏览器生成的 session_id 过滤，不同匿名会话之间不互相可见；启用登录后可把会话关联到 user_id（《02》第6.2节 功能 6）。
- 输入：会话标识 session_id（第一版）或 user_id（条件下启用登录后）；已生成的回答与引用证据；提问时间。
- 处理：
  1. 用户提交问题时写入 question，记录问题、提问时间与 session_id；
  2. 回答生成后写入 answer，通过 question_id 与对应问题关联；
  3. 本次回答引用的证据写入 answer_evidence，通过 answer_id 与对应回答关联；
  4. 用户查看历史记录时，后端按 session_id 过滤 question（启用登录后可按 user_id 关联）；
  5. 通过 question_id 与 answer_id 关联还原完整的问答历史，并按提问时间展示；
  6. 用户选择其中一条记录时，回看该次回答及其引用证据——回看只还原 question、answer 与 answer_evidence 三表的内容，**不重新渲染**当时展示的图谱路径视图（图谱路径存于 answer.graph_path 字段，**不建立独立的路径表**，因此表数量仍为六张）；如需查看相关图谱关系，回到 UC-03 重新查询。
- 输出：按会话隔离的历史问答列表，包含问题、提问时间、回答与引用证据。
- 前置条件：提问已完成且回答已生成；question 已写入 session_id。
- 后置条件：同一浏览器会话可以回看此前的问答；不同匿名会话之间不互相可见；历史记录可用于实验统计。
- 边界与不做的事：**历史记录不需要独立的表**——question 记录问题、answer 记录回答、answer_evidence 记录答案引用的证据，三者通过 question_id 与 answer_id 关联即可还原完整的问答历史，表数量仍为六张（《02》第6.2节 功能 6、第9.1节）；不做多角色与细粒度权限，第一版不启用登录时也不提供跨会话或跨用户的全局历史；历史记录不涉及个人隐私数据（《02》第6.1节）。
- 来源追溯：《02》第6.2节 功能 6；《02》第6.1节；《02》第9.1节；《02》第12.7节。

#### UC-01 提交问题并获取答案

- 参与者：普通用户。
- 前置条件：文本已入库并完成向量索引构建与图谱写入；Embedding 模型与大语言模型接口可调用；问题非空且长度在接口限制之内；第一版无需登录，若条件下开启"仅登录"，则本用例以登录成功为前置条件。
- 主流程：
  1. 用户进入问答页面，页面固定显示"数据截至：YYYY-MM-DD"；
  2. 用户输入自然语言问题并提交，前端携带浏览器生成的 session_id；
  3. 系统校验输入非空且长度在限制之内；
  4. 问题分析：判定问题类型与是否需要图谱扩展，识别实体与时间约束；
  5. 文本检索：在向量索引中检索候选文本块；
  6. 图谱检索：按问题需要执行 0 跳、1 跳或 2 跳扩展；
  7. 时间过滤：带时间约束的问题按 event_time 过滤；"最近"解释为 event_time 落在数据截止时间前 30 天以内，"最新"取符合条件的、event_time 最大的事件，"近期"取数据截止时间前 90 天以内，与《02》第10.3节 的判定规则表一致；
  8. 证据排序：合并文本检索与图谱检索的结果并排序；
  9. 大模型生成：基于证据生成答案，不使用数据截止时间之后的信息，不在证据不足时用训练语料中的时间信息补全答案；
  10. 落库：写入 question（含 session_id 与提问时间）、answer、answer_evidence；
  11. 返回答案，页面同时显示"数据截至：YYYY-MM-DD"与本次问题所用的判定区间；
  12. 若问题为开放式分析问题，在页面与答案中同屏标注"模型分析（非公开事实）"，不计入任何指标。
- 备选流程／异常流程：
  - A1 输入为空：提示用户输入问题，不调用检索与模型接口（《02》第7节 异常处理）；
  - A2 模型接口超时：按统一封装设置超时与重试，仍失败时给出明确提示，页面不失效，且错误提示不泄露密钥与内部堆栈信息；对相同问题可使用缓存结果（《02》第7节、《04》第8.4节 风险五）；
  - A3 图谱查询为空：返回文本检索得到的证据并说明图谱侧无匹配；此时按未使用图谱扩展处理并标注"本次回答未使用图谱扩展"（《02》第7节、《02》第13节）；
  - A4 问题涉及数据截止时间之后的信息：按数据截止时间解释判定基准并说明数据边界，不编造数据截止时间之后的事实（《02》第10.3节）；
  - A5 0 跳问题或未启用图谱扩展的实验组：正常返回文本证据，并在图谱路径区域标注"本次回答未使用图谱扩展"，不展示虚构路径（《02》第13节）；
  - A6 开放式分析问题：按第 12 步标注"模型分析（非公开事实）"，只用于答辩演示、页面展示与失败案例分析，不作为核心准确率依据，不计入任何指标（《02》第12.9节）。
- 后置条件：question、answer、answer_evidence 三条记录可关联还原本次问答；本次问答可在历史记录中回看；若属于定量实验问题，其指标按《02》第12.7节 的口径统计。
- 涉及的功能需求编号：FR-04、FR-05、FR-06；触发图谱扩展时同时涉及 FR-03。

说明：本用例必须向用户说明"最新／最近／近期"类问题的判定基准是数据截止时间而不是系统运行当天，一律按 event_time 判定，答案中注明所用判定区间（《02》第10.3节、第13节）。

#### UC-03 查看图谱（含多跳路径查询）

- 参与者：普通用户。
- 前置条件：图谱已完成写入并通过一致性检查；查询条件非空。
- 主流程：
  1. 用户选择查询条件，可以是实体、事件、关系或时间区间；
  2. 提交查询；
  3. 系统在 Neo4j 中检索匹配的实体、事件与关系；
  4. 按需要沿图谱关系做 1 跳或 2 跳扩展；
  5. 带时间约束的查询按 Event 节点的 event_time 过滤；
  6. 以可视化方式展示实体、事件与路径；
  7. 查看路径上除 EVIDENCED_BY 外每条关系的 source_doc_id、source_chunk_id 与 confidence（EVIDENCED_BY 的证据为其指向的 Document 节点）。
- 备选流程／异常流程：
  - C1 图谱查询为空：提示未检索到匹配的实体、事件或路径，并说明可调整实体名称或时间区间（《02》第7节 异常处理）；
  - C2 同一事件存在多份来源：按 publish_time 排序展示，发布时间最早的一份作为主要来源，其余作为补充证据（《02》第9.2.5节）；
  - C3 查询涉及的关系不在 9 条核心关系之内：不临时增加关系类型，按本体适用边界记录并提示（《02》第12.3节）。
- 后置条件：除 EVIDENCED_BY 外的每条展示关系均可回溯到文档与文本块（EVIDENCED_BY 本身即证据关系，其证据为该关系指向的 Document 节点）；路径深度与本次查询设定的检索深度一致。
- 涉及的功能需求编号：FR-03；查看关系证据属性时同时涉及 FR-02。
