## 三、切分口径与参数

### 3.1 固化参数（`config.CHUNK`，本阶段固化的 TBD 之二）

单位一律为**字符数**（中文按字符计，不按词计）。以下参数**封版后不得更改**；改参数等于换数据集版本（《12》第五节 硬约束 5）。

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `target_chars` | 400 | 目标长度 |
| `max_chars` | 512 | 单块上限（与 Embedding 的 `max_seq_length = 512` 对齐） |
| `min_chars` | 128 | 单块下限；整篇正文短于 `target_chars` 的文档豁免（登记在 `chunk_stats.json` 的 `min_chars_exemptions`） |
| `overlap_chars` | 50 | 重叠窗口，`50 / 400 = 12.5%` |
| `boundary_priority` | `["\n\n", "\n", "。", "！", "？", "；", "…", ".", "!", "?", ";"]` | 边界优先级：**段落 > 换行 > 句末标点 > 分号 > 省略号 > 半角句末标点**；按序试探，全部落空才硬切 |
| `strip_rules` | true | 切分前剥离行内空白与规则行 |
| `DOC_ID_STRIDE` | 1000 | `chunk_id = doc_id * 1000 + chunk_index` 的步长 |
| `MIN_DOC_CHARS` | 80 | 低于该长度的文档整篇跳过（清洗环节） |
| `MAX_CHUNKS_PER_DOC_WARN` | 120 | 单篇文本块数的**告警**阈值，只报告、不截断 |

**重叠窗口与"一个文本块只算一个证据"**：`overlap_chars(50) < min_chars(128)`，重叠区只用于衔接上下文，**不足以在相邻两个文本块里各自构成完整证据**。这直接满足《12》第五节 硬约束 5 与《02》第12.7节 第二步（一个文本块只算一个证据），也避免 Complete Evidence Recall@K 在定义上不可达。

**切分前的编号步长预检**：`chunk.py` 在写盘前先逐篇投影文本块数，只要有一篇超过 `DOC_ID_STRIDE`（单篇 1000 块），就点名 `doc_id`／标题／字符数／投影块数并以非零码中止——**只报告，绝不截断正文、绝不丢弃文档**。投影与实际切分共用同一实现，故投影块数即落盘块数。本轮 `over_long_documents = []`。

### 3.2 编号规则（《12》第五节 硬约束 6、7、8）

* `chunk_id = doc_id * DOC_ID_STRIDE + chunk_index`（`config.chunk_id_for`）。例：`doc_id = 1001` 的第 0 块是 `1001000`、第 1 块是 `1001001`。
* 该式是**双射**：`config.split_chunk_id` 可反查出 `(doc_id, chunk_index)`；本轮 `split_chunk_id_roundtrip_ok = 707/707`，`mismatched = 0`。
* `chunk_index` 在文档内**从 0 连续递增且不重复**（对应唯一键 `uk_chunk_doc_index(doc_id, chunk_index)`）；每篇文档**至少 1 个文本块**。
* 三级映射链路 `vector_id → chunk_id → doc_id` **双向可查**：`index\vector_map.jsonl` 给出正向（vector_id → chunk_id → doc_id），`chunks.jsonl` 的 `vector_id` 给出反向（chunk_id → vector_id）。

## 四、向量化口径

### 4.1 Embedding 模型与版本（本阶段固化的 TBD 之一）

本阶段必须在向量化之前固化 Embedding 模型并写入元信息（《12》第2.3节、第五节 硬约束 10），原因是向量索引一旦建立，换模型就要**全量重建**，而《02》第12.4节 又要求所有对比组与消融组用同一个 Embedding 模型——它不能拖到第 7 阶段。

| 项 | 取值 | 出处 |
| --- | --- | --- |
| 模型名称 | `BAAI/bge-small-zh-v1.5` | `config.EMBEDDING`；实测记录见 `index\build_meta.json` |
| 模型版本（revision） | `7999e1d3359715c523056ef9478215996d62a620` | 同上；`revision_matches_config = true`、`pinned_revision_in_cache = yes` |
| 向量维度 | 512 | `build_meta.json` 的 `dim` |
| 池化方式 | `cls` | `build_meta.json` 的 `pooling` |
| 相似度 | 余弦（向量 L2 归一化后内积等价） | `normalize_embeddings = true`、`similarity = cosine`、`metric = inner_product` |
| 最大序列长度 | 512 | 与 `CHUNK.max_chars = 512` 对齐；`chunks_over_embedding_max_seq_length = []` |
| 查询指令前缀 | 空（文档与查询同向编码） | `query_instruction = ""` |
| 运行设备／批大小 | CPU ／ 32 | `device = cpu`、`batch_size = 32` |

**选型理由**：中文检索的常用基线、CPU 可跑、维度小、索引可全量重建；模型已下载至本地 HuggingFace 缓存，**离线可加载**（`local_files_only = true`），符合"实验期间不得更换"的固定配置要求。

### 4.2 向量索引与三级映射链路

* **索引类型**：`IndexFlatIP`（归一化向量 + 内积 = 余弦相似度；第一版规模小，用**精确检索**）。构建用的 `faiss-cpu = 1.15.1`、`numpy = 2.5.1`。
* **索引文件**：`index\faiss.index`，实测 `ntotal = 707`、`dim = 512`。
* **映射文件**：`index\vector_map.jsonl`，707 行 `{"vector_id", "chunk_id", "doc_id"}`，双向可查；`vector_id = 向量索引行号`，按 `chunk_id` 升序分配，故 `vector_id` 取值域恰为 `0..706`，无缺号、无越界。
* **元信息文件**：`index\build_meta.json`（模型名与 revision、维度、条数、构建时间、索引类型、`build_time = 2026-09-25T15:46:54+08:00`、`build_seconds = 19.763`）。
* **统计口径**：《02》第9.3节 要求的一致性检查（向量条数 = 文本块条数）在本阶段**只做条数一致性检查**，不做检索、不排序、不算任何指标（《12》第七节 非目标 7）。实测：向量条数 = 文本块条数 = **707**，无 `vector_id` 为空的文本块，去重后 `distinct_vector_ids = 707`。
* **术语口径**：本项目一律称 FAISS 为"**向量索引**"或"**向量检索组件**"，向量索引中**不保存权威文本，只保存向量与索引结构**——权威文本在数据库的 document 表中（《10》第4.4.6节 的三处存储分工）。

### 4.3 本阶段向量化的边界

本阶段向量化**只覆盖数据准备所需的三件事**：固化 Embedding 模型与版本、建立向量索引、落盘 `vector_id ↔ chunk_id ↔ doc_id` 映射。**N（向量检索候选数量）、K（Top-K）与 Context Token Budget 在本阶段保持 TBD**，由第 7 阶段做检索预实验时一并固化（《12》第2.3节）；本阶段不写死任何检索参数。

### 5.4 `company_list` 允许为空的类别与原因

| category | `company_list` 口径 | 实测篇数 | 原因 |
| --- | --- | --- | --- |
| 公告 | **必须非空** | 49（`[]` 0 篇） | 公告由上市公司依法披露，天然对应一家或多家特定公司（以巨潮接口的 `secCode` 为准） |
| 财经新闻 | **必须非空** | 25（`[]` 0 篇） | 财经新闻的入选条件就是正文提及本公司名称或 6 位代码，无关联公司的文章不进候选池 |
| 政策文件 | 允许为 `[]` | 15（15 篇为 `[]`） | 政策文件是国务院文件与部门文件（如国务院、各部委发布的办法、规划、指南），**多数不涉及特定上市公司**；强制非空只能靠编造关联 |
| 监管公开信息 | 允许为 `[]` | 10（10 篇为 `[]`） | 监管公开信息是证监会行政处罚决定书，当事人为自然人、会计师事务所等**非上市公司主体**，多数不涉及特定上市公司；强制非空只能靠编造关联 |

**两种"空"的区别必须分清**：允许的是**空数组 `[]`**（表示"明确不涉及特定公司"），**不允许 `null`**（表示"该字段没有取值"）。二者的语义不同：前者是有效取值，后者是数据缺失。实测 `null_or_missing_company_list = 0`、`non_list_company_list = 0`，即 99 篇全部是合法取值。数据集覆盖的公司**集合**恰好等于 T2 选定的 10 家（`equals_configured_set = true`，`missing_codes`／`extra_codes` 均为空）。

### 5.5 `url` 的取值与为空口径

* **取值规则**：`url = content_url`，缺失时回退 `page_url`（`clean.py`）。因此 `url` 只在 `content_url` 与 `page_url` **同时为空**时才为空。
* **本轮实测**：99 篇全部非空、`distinct_urls = 99`、`urls_blank = 0`、`url_fallback_to_page_url_doc_ids = []`（即没有任何一篇用到回退分支）。
* **硬约束 3 允许"访问受限时可为空"**——《12》第五节 硬约束 3 明确 `url` 在访问受限时可为空，但必须在《13》说明哪些来源属于此类。**四类来源中风险最高的是财经新闻**：三个站点的正文页若对某篇文章设限（登录墙、付费墙、已下线），按"绝不用生成文本、占位文本或改写文本充数"的纪律，只能保留其余元数据而放弃该 `url`，此时该篇的 `url` 为空。公告（巨潮静态 PDF）、政策文件与监管公开信息（政府网站静态页）的正文地址均为公开资源，且 `url` 有 `page_url` 兜底，**为空的情形在这三类上不成立**。
* **本轮为空的情形未发生**：四类来源在本轮采集窗口内均可正常访问，故封版数据集中 **0 篇为空**。若未来某篇为空，`document.url` 列本身在《10》第4.4.1节 中即为"可空"，无需改表结构。

### 6.5 版本不可变与升版规则

* `阶段05-数据准备\数据集\` 下的四个版本目录（`v1.0`／`v1.1`／`v2.0`／`v2.1`）均已**封版**。封版后**不得就地修改任何文件**——不新增、不删除、不改写、不重跑覆盖。理由是数据集是第 6～10 阶段所有实验的共同输入，若版本目录内的文件可以被就地修改，"实验不可复现"就无法排除（《12》第4.2节）。

* **改切分参数等于换数据集版本**（《12》第五节 硬约束 5）。换 Embedding 模型同样需要全量重建索引、并升 `dataset_version`。
* 本阶段参数与版本的唯一来源是 `代码\数据准备\config.py`；任何脚本都不得绕过它写死参数，需要改参数时改 `config.py` 并升版本。
