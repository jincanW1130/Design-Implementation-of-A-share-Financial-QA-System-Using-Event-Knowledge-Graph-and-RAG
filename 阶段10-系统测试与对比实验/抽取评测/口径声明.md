# 口径声明（可直接引用进论文）

## 一、这次评测的参照集是什么

本次 RQ1 抽取评测的对照物是**模型参照集**，路径为
`阶段05-数据准备\数据集\抽取评测集\v2.1\自动标注\提准\{dev,test}.auto.repaired.jsonl`
（Dev 60 ＋ Test 200 ＝ 260 条，单位是文本块，编号即 `chunk_id`）。

它的生成链条是：`deepseek-flash` 按 Prompt `stage6-auto-annotate-v1.0-flash` 在 temperature 0 下逐条自动标注
（`status = auto_annotated`，每条带 `provenance` 与 token 账），再由**离线** lint（`auto_annotate_lint.py`，规则 v1.2）
扫出硬命中条目，只对这些条目做**定向修复**（`auto_annotate_repair.py`，Prompt `stage6-auto-annotate-flash-repair-v1.0`），
修复后硬命中 0 处／0 条；最后有一次 40 条独立复核（由本项目决策者执行）的 4 处修正。

**它不是人工标注，也不是人工金标准，未逐条人工复核。**

## 二、为什么不是人工的

因为人工标注**没有做**。抽取评测集的交付文件
`阶段05-数据准备\数据集\抽取评测集\v2.1\{dev,test}.jsonl` 的 `annotation` 槽位
（`entities`／`events`／`relations`／`times`／`ontology_boundary_log`）**全部为空**、
`status = pending_human_annotation`——这是《16》第 7.6 节 的冻结契约：
「交付槽位不得由脚本、规则或模型代填」。本次评测**没有**、也不会把那 260 条参照集内容写进交付槽位，
而是另立一份公开、可复算的参照集，并把系统抽取结果与它对照。

## 四、指标该怎么读

1. 只能表述为「**模型参照集口径下的抽取表现**」。
2. 读数是「系统抽取结果 vs 模型参照集」在实体／事件／关系／时间四类任务上的 Precision／Recall／F1，
   Dev 60 用于说明调优过程，Test 200 是独立评测段，合计 260。
3. **Dev 与 Test 用同一把尺子、同一份参照集、同一套匹配判据**；判据逐类写在《抽取评测报告》第二节。
4. 分类型读数（8 类事件、9 条关系、5 类实体、3 类时间）比总读数更可靠——
   第三方盲标复核显示：条目级「完全一致率」很低（12.5%～30.0%），而**分层指标**
   （实体类型一致率 κ 0.98～1.00、事件类型分布 TVD 0.06～0.13）可跨厂商复现。
5. 参照集与抽取器**同端点、同模型家族**（主参照集用的 `deepseek-flash` 更与抽取器同模型），
   同源自证风险被降低但没有消除，两者之间的一致**不构成独立验证**。
6. 偏倚方向已登记：**参照集比多模型共识更紧、以漏标为主，因此抽取的 Precision 与 Recall 都被低估。**

## 五、不得怎么读

* **不得**把这些数字写成「准确率」或「人工金标准下的抽取准确率」。
* **不得**出现以人工标注为对照物的表述（如把参照集称作人工标注结果）。
* **不得**把参照集与抽取结果之间的一致当作「独立验证」。
* **不得**把某一类的总读数单独拿出来支撑「抽取质量达标」——必须连**分类型读数**与
  《抽取评测报告》第六节的已知限制一起引用。
* **不得**把这套读数当检索 gold 或检索测试集使用（它只可作出题素材，且必须保持「模型参照集」定性）。
