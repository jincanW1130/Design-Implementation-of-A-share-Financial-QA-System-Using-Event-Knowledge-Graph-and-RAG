| 组 | 题数 | 每次调用的模型 | 调用次数 |
| --- | --- | --- | --- |
| A（＝Baseline 2＝纯 Vector RAG） | 120 | `deepseek-flash` | 120 |
| B（＝A＋1-hop KG） | 120 | `deepseek-flash` | 120 |
| C（＝Method＝A＋2-hop KG） | 120 | `deepseek-flash` | 120 |

| **合计** | **720 题组** | — | **720 次** |

* **基数 720 次**；按《21》v1.3 的**空正文重试规则**（请求成功但正文为空串时以完全相同的配置重试一次），

  B1 不跑检索，因此 **B1 是六组里最便宜的一组**（每次只有 1 次模型请求）。
* 每次「题 × 组」的调用次数在产出里逐题可数：`answer_trace.jsonl` 的 `attempts` 数组长度。

## 四、预计时长与费用量级

### 4.1 时长（依据＝**实测**，不是估计）

实测来源：`阶段10-系统测试与对比实验\对照产出_v13\{A..E}\answer_trace.jsonl`
（30 题 × 5 组 ＝ 150 条 trace 行，逐行的 `attempts[].seconds` 求和，即"该题该组的模型生成净耗时"）：

| 统计量 | 读数 |
| --- | --- |
| 样本 n | 150 |
| 均值 | **6.685 s** |
| P95（最近秩法） | **21.799 s** |
| 最大 | 51.622 s |

折算到 120 题 × 6 组 ＝ 720 次：

| 口径 | 纯生成时间 | 加上检索侧子进程开销的**墙钟**预计 |
| --- | --- | --- |
| 按均值 | 720 × 6.685 s ≈ **80 分钟（1.34 h）** | **≈ 2.7 h** |
| 按 P95 | 720 × 21.799 s ≈ **262 分钟（4.36 h）** | **≈ 6.4 h** |

检索侧开销的算法：A～E 五组每题每次 spawn 一个 `run_query.py` 子进程，含加载 Embedding 模型与
图谱 CSV，实测约 **8～12 s**／次；120 题 × 5 组 × 8～12 s ≈ 1.3～2.0 h。

> **结论**：给正式跑留 **3～7 小时**；且**必须串行跑**（脚本逐题串行，刻意不并发——第 9 阶段的
> 实测已证明背靠背并发会撞服务端限流：连续 100 次只有 60 次成功、40 次 429，见
> `评审\第3步执行记录.md` 第 2.2 节）。中途可以随时 Ctrl-C，已完成的题会保留（见第六节）。

### 4.2 费用量级

**token 消耗的实测依据**（同一批 150 条 trace 行）：

| 量 | 均值 | 说明 |
| --- | --- | --- |

## 五、产出落点与 SHA-256 记录方式

### 5.1 落点

```
阶段10-系统测试与对比实验\对照产出_正式\
├── A_vs_C_对照报告.md            ← 主交付：核心集主结果 ＋ 压力子集单独一节 ＋ 逐子集 ＋ 机检量 ＋ B1 如实标注
├── A_vs_C_对照.json              ← 同上，机器可读（含 frozen／question_counts／call_budget／subsets）
├── 产出SHA256.json               ← 全部产出的 SHA-256 与字节数
├── A\
│   ├── answer_trace.jsonl        ← 一行一题；含 evidence／graph_payload／token_account／attempts／gates
│   └── qa_records.jsonl          ← question／answer／answer_evidence 三表语义（《10》表 4-6 字段）
├── B\ … （同 A）
├── C\ … （同 A）
├── D\ … （同 A）
├── E\ … （同 A）
├── B1\
│   ├── answer_trace.jsonl        ← 与 A～E **同构**；另含 retrieval_used／baseline_id／baseline_annotation
│   └── qa_records.jsonl
└── 逐题\{组}\{题号}\
    ├── answer_trace.jsonl／qa_records.jsonl／prompt_snapshot.json   ← 该题的原始产出（冻结入口写的）
    └── b1_case.json              ← 仅 B1：该题用的装配输入（可复核"0 证据、无图谱路径"）
```

`prompt_snapshot.json` 在**逐题目录**里由冻结的 `prompt.write_snapshot()` 写出，不在组目录里；
它登记的是 Prompt 模板 v1.0 的七区块快照与模板 SHA-256（与 A～E 逐字相同）。

### 5.2 SHA-256 记录方式

脚本在每次运行结尾写 `对照产出_正式\产出SHA256.json`：

```json
{
  "files": {
    "A_vs_C_对照报告.md": {"sha256": "…", "bytes": 12345},
    "A_vs_C_对照.json":   {"sha256": "…", "bytes": 67890},
    "A/answer_trace.jsonl": {"sha256": "…", "bytes": …},
    "A/qa_records.jsonl":   {"sha256": "…", "bytes": …},
    "A/prompt_snapshot.json": {"sha256": "…", "bytes": …},
    "…": {"sha256": "…", "bytes": …}
  }
}
```

**复核方式**（重跑之后任何一项与登记值不同，就说明该文件变了——尤其 `prompt_snapshot.json`
与 `answer_trace.jsonl` 的 `prompt_sha256` 字段）：

```powershell
cd C:\Users\15129\Desktop\毕业设计
python -c "import json,hashlib,os,sys;d=json.load(open(r'阶段10-系统测试与对比实验\对照产出_正式\产出SHA256.json',encoding='utf-8'));base=r'阶段10-系统测试与对比实验\对照产出_正式';bad=[k for k,v in d['files'].items() if hashlib.sha256(open(os.path.join(base,k.replace('/',os.sep)),'rb').read()).hexdigest()!=v['sha256']];print('不一致：',bad or '无')"
```

**登记进论文时**：把 `产出SHA256.json` 随产出一起归档，论文附录给出**报告文件**与
**各组 answer_trace.jsonl** 两项的 SHA-256 即可（其余可由它们派生复核）。

**确定性说明**（不得含糊）：

* 记录层时间与会话标识是**固定值**（`--now 2026-10-02T00:00:00+08:00`、`--session-id S-正式对照`），
  产出里**不写运行时刻**，故同一输入的产出可逐字节复现；
* **模型侧输出不承诺逐字节一致**（《21》第五节 硬约束 17）——`answer_trace.jsonl` 里的
  `body_text` 在两个不同运行之间可以不同，这是模型侧的固有性质，**不是**本脚本的缺陷；
  `prompt_sha256`／`token_account`／`evidence` 三项是确定性量，重跑必须逐位相同。

## 六、断点续跑与补跑语义

### 6.1 语义：**按「组 × 题号」合并写回，不覆盖已完成的题**

`{组}\answer_trace.jsonl` 与 `{组}\qa_records.jsonl` 的聚合是
**"新行按 key 覆盖旧行、其余行原样保留"**（key：trace 用 `qid`，qa_records 用 `answer_id`），
然后在**本次 `--groups` 指定的组**内重算指标并重出报告。

由此得到三条可依赖的性质：

1. **中断可续**：Ctrl-C／断电／额度耗尽之后，已完成的题已经在组文件里；
   重跑同一命令会重跑**所有**题（脚本不自动跳过已完成题——它逐题无条件调用）。
   要"只补没跑的"，用 `--only-qids`（见下）。
2. **单题补跑不破坏其他题**：补跑几题不会把已完成的 120 题抹掉。
3. **报告可 0 调用重出**：`--report-only` 不进入生成循环。

### 6.2 补跑失败题

## 七、失败处理

| 失败现象 | 脚本的行为 | 你该做什么 |
| --- | --- | --- |

| 题集不存在 / schema 不过 | 退出码 2（题集不存在），或在 `--preflight` 里报 FAIL | 先把题集建好或修正字段 |
| 桥接记录被并发写入者占用 | **拒绝运行**并指名冲突路径 | 等另一个任务结束，或用 `--only-qids` 换题 |
