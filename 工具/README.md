# 工具

本目录存放项目自用的脚本，不属于交付物，也不参与文档编号。

| 脚本 | 用途 |
| --- | --- |
| `跨文档核验.py` | 对工作区全部 Markdown 做 14 项一致性核验（A～N），**每次产出新文档后都要重跑** |
| `验收第4阶段文档.py` | 《10》的专项验收：逐条对应《09》第七节 的验收标准与 第四节 的 13 条硬约束 |
| `验收第5阶段数据.py` | 《13》与数据集 v1.0 的专项验收：逐条对应《12》第八节 的 19 行验收标准（共 99 项，含真实重跑时 103 项；S 组是索引集中度守卫） |

## `跨文档核验.py`

对工作区里的 Markdown 文档做一遍机器可复现的一致性核验。**每次产出新文档后都应重跑**，尤其是第 4 阶段及以后每次新增 `NN-` 文档时。

运行：

```powershell
python 工具\跨文档核验.py
```

不带参数时，工作区取本脚本所在目录的上一级；也可以传入其它路径：

```powershell
python 工具\跨文档核验.py "C:\Users\15129\Desktop\毕业设计"
```

退出码 `0` 表示全部通过，`1` 表示存在失败项（明细在输出里）。

### 参与核验的文档范围

根目录的 `*.md` ＋ 每个 `阶段NN-…\` 目录**一层**内的 `*.md`。**不参与核验**的两类：`阶段04-系统总体设计\_分节源文件\` 内的分节稿（它们是《10》的输入，不是独立文档）与 `阶段02-…\_归档_…\` 内的归档过程文件。分节稿不参与核验，因此改完分节稿必须重跑拼装脚本，否则交付文档与源文件会不一致。

### 检查项

| 编号 | 检查内容 |
| --- | --- |
| A | 文档规模（行数按文本行计，不含文件末尾换行产生的空行；KB＝字节÷1024），并检查文件名互不重名 |
| B | 表格列数一致性（跳过 ```` ``` ```` 代码块），统计表格块总数 |
| C | 跨文档节号引用可解析性：每个 `《0N》第x.y节` 是否真的存在于被引文档中（含中文序号章节） |
| D | 《07》第1.3节 来源清单覆盖：正文引用的节是否都在表中，**按文档分别归属节号** |
| E | 需求追溯矩阵的来源是否都被对应条目的"来源追溯"覆盖 |
| F | 第3.8节 功能需求汇总表 与 第7.2节 追溯矩阵 的 FR 来源是否逐字一致 |
| G | 需求编号覆盖（FR-01～06／UC-01～07／NFR-01～06） |
| H | 作废术语残留（裸 `Evidence Recall`，排除修订留痕） |
| I | 未限定范围的证据属性表述（"每条关系…source_doc_id"一类，须带"除 EVIDENCED_BY 外"） |
| J | 边界禁用词出现在"引入／使用"语境（仅报告，需人工确认语境） |
| K | 文档内以反引号提到的 `.md/.py/.html/.csv/.docx/.pdf/.png/.svg` 路径是否存在（含阶段目录、归档目录与旧路径别名） |
| L | 工作区内的 `0N-` 文档是否都登记在《00-项目总览与索引》中 |
| M | 目录结构：五个阶段目录齐全、`_分节源文件\` 存在、根目录只留《00》与《02》、每份带号文档都在阶段目录里、`10-` 同名目录与旧 `文献调研\` 目录已消除 |
| N1 | 《02》的版本号在**标题末尾**、文档信息表的**版本字段**与 第1.2节 **修订记录末行**三处是否一致（**门禁项**；2026-09-25 新增：v2.4／v2.5 两次登记只改了 第1.2节、没有回改表头，版本号漂移了两个版本而无人发现） |
| N2 | **引用方版本审计**：只审计**依据声明行**（含"依据／上游／需求来源"），且版本号须紧跟在《02…》之后、中间不再出现其他《》引用；被引版本非当前版本时，**同一行只要提到当前版本、或带版本链说明，即视为已交代**，否则计为过期引用。记录类文件（`05-`／`06-`／`08-`／`11-`）按留痕排除。**默认只报告**（`[WARN]`），加 `--strict-citations` 转为门禁。2026-09-25 校准过一次：原口径只认"版本链／未改变"等字样，把「（编制时为 v2.5，第 5 阶段完成后已登记为 v2.6）」这种同样讲清了版本链的写法误报为过期——**假阳性改的是守卫，不是文档** |

`跨文档核验.py` 查全工作区的通用一致性，本脚本查 **《10》自身**是否满足《09》写下的验收标准。两者分工不重叠，每次改完《10》都要两个都跑。

运行：

```powershell
python 工具\验收第4阶段文档.py
```

三组检查：一、《09》第七节 的验收标准（7 个小节标题与《02》第15节 第四章逐字一致、六层名称与顺序、六个模块名称与顺序、6／8／9 口径、六张表、Method＝C 与 Baseline 2＝A、Top-K 四句契约逐字、FR／UC／NFR 落点）；二、《09》第四节 的 13 条硬约束；三、图与表编号连续性与**文档头声明的图表数量与实测一致**（第三组是为了防止拼装脚本里的陈述与正文脱节——`10-` 曾出现"表 4-12 共 12 张"与实际 13 张不符）。

## `验收第5阶段数据.py`

`跨文档核验.py` 查全工作区的通用一致性；本脚本查**第 5 阶段的数据侧交付**是否满足《12》第八节 写下的验收标准，即《13-数据准备（第五阶段）.md》与数据集 v1.0 本身。两者分工不重叠，第 5 阶段的收口结论以两个脚本的退出码均为 0 为准。

运行：

```powershell
python 工具\验收第5阶段数据.py
python 工具\验收第5阶段数据.py --with-idempotence    # 另在临时目录真实重跑 T4a→T5
python 工具\验收第5阶段数据.py --dataset <数据集目录> --doc <《13》路径>
```

共 19 组、99 项检查（`--with-idempotence` 时 103 项；脚本里 "检查项合计（A～S）" 一行是 97 的中间计数，另有 2 项在收尾阶段计入，**以末行 "最终：检查项" 为准**）：文档结构、《13》必备小节、目录自包含、`meta\dataset.json` 逐项重算比对、必需字段、三个判重键、监管标题构造规则、`company_list` 口径、公司集合、编号公式、块长与重叠、向量条数、时间口径、类目与来源、幂等、越界排除、禁用术语、《00》登记，**以及 S 组的索引集中度守卫**（单篇 ≤ 25%、前 5 篇合计 ≤ 60%、同一标题不得跨公司复用）。**凡是能从数据集文件重算的数值一律重算后比对**，不拿 `reports\consistency_report.json` 当独立证据（个别处读报告比对的，输出里明确标注）。

S 组的两条阈值是**本工具的守卫阈值**，刻意不读 `代码\数据准备\config.py`：一篇文档吃掉索引是**数据集缺陷**，必须让验收失败；而合理的块长均值／最大值属于数据集参数，归 config。这一条是本文件里"参数一律取自 config"的**唯一例外**，写在这里以免下次被当成疏漏。

## `验收第6阶段.py`

`跨文档核验.py` 查全工作区的通用一致性；本脚本查**第 6 阶段（事件抽取与知识图谱）的交付侧**是否满足《15-第6阶段任务书（事件抽取与知识图谱）》第八节 写下的验收标准，即《16》交付文档、图谱导出物、消歧／去重产物与缓存、抽取评测集与 `代码\抽取与图谱\` 的五个脚本。第 6 阶段的收口结论以两个脚本的退出码均为 0 为准。

运行：

```powershell
python 工具\验收第6阶段.py                       # 默认 --profile pilot：核验试跑产物（12 篇）
python 工具\验收第6阶段.py --profile v21         # 核验全量产物（图谱导出\v2.1\，读到什么算什么）
python 工具\验收第6阶段.py --no-replay           # 只做静态检查，跳过镜像重跑（相应各项记 SKIP）
python 工具\验收第6阶段.py --keep-tmp            # 保留镜像重跑用的临时目录，便于事后复核
python 工具\验收第6阶段.py --work-root <目录> --export-dir <目录> --doc16 <《16》> --p00 <《00》>
                                                 # 覆盖落点：负向自测与提前演练用
```

**profile 开关**（路径一律经 `代码\抽取与图谱\config.pipeline_paths()` 解析，不在脚本里写死）：`pilot`（默认）核验 `阶段06-事件抽取与知识图谱\_试跑_图谱管线\` 与 `代码\抽取与图谱\_试跑\extracted.jsonl`；`v21` 核验 `阶段05-数据准备\数据集\_抽取缓存\v2.1\图谱管线\` 与 `阶段06-事件抽取与知识图谱\图谱导出\v2.1\`。全量跑完后换 `--profile v21` 即可，脚本不需要改一个字。

共 24 组（A～X）、100 项检查，逐行对应《15》第八节 的 **29 行**（含末行「全套检查通过」；行 → 组映射写在每组标题里）：A 《16》的 9 个必备小节／B 本体一致性与端点类型／C 证据属性口径／D 证据可回溯（chunk → doc）／E Event 六项核心属性与 event_time 空值登记、role 与 ISSUED_BY／F BELONGS_TO 有效期与 `data_cutoff_time` 不落图／G 编号显式唯一／H 消歧可复算／I 去重可复算／J 导出物与缓存重放逐字节一致／K 重放零模型调用／L 缓存位置与仓库边界／M 导出物不复制正文／N 评测集 260 条、不重叠、分层容差与逐项差异登记／O 表 15-C／15-D 重算与证据不足登记／P 抽取配置四要素与《02》12.4 仍为 TBD／Q 未新增第七张表／R 数据集只读指纹／S 幂等与续跑／T 五个脚本可单独执行且参数取自 config／U 密钥不入仓库／V 禁用连写／W 《00》索引登记／X 收口。**凡是能从数据集、导出物与缓存重算的数值一律重算后比对**，`graph_check.json` 只作参考不出现在任何判定链上。

**降级口径**：只有真的「全量才可能成立」的检查才降级——`v21` 下要求 8 种事件类型与 9 条核心关系在导出物中全覆盖，`pilot`（12 篇）下记 `[SKIP]` 并写明覆盖数；数据集指纹找不到登记基线时 `pilot` 记 SKIP、`v21` 记 FAIL。其余检查（《16》必备小节、260 条评测集、证据可回溯、四要素、《02》TBD、数据集只读等）**不做降级**：试跑期间该失败就失败，如实记入失败项。

**只读纪律**：本脚本对交付物只读。需要重跑的 H／I／J／K／S 组把 `代码\抽取与图谱\*.py`、v2.1 的正文与文本块、抽取缓存、抽取结果与管线产物**镜像**到系统临时目录，在那里复跑 `run_all.py`、四个环节脚本与 `--from dedup_events` 续跑，再与原产物逐字节比对（`generated_at` 与缓存指纹字段按 `config.GRAPH_PIPELINE["excluded_from_byte_compare"]` 排除）。镜像子进程的**环境里显式摘掉 `LLM_API_KEY`**：缓存缺一篇就硬失败，绝不静默调用模型。临时目录默认删除，`--keep-tmp` 可保留。

**本工具自带的常量（「参数一律取自 config」的两处例外，已在脚本内就地注释）**：① 数据集指纹基线的候选落点（任务书未规定基线文件名：优先 `<管线工作目录>\dataset_fingerprint.json`，否则回退第 5 阶段封版清单 `代码\数据准备\勘察\manifest_宽口径_最终.json`）；② 提示词模板／文档字符串内的日期示例不计入「写死日期」。表 15-C／15-D 重算用的正则、本体与 role 取值、编号规则、导出字段与抽样参数全部取自 config／《10》，不另外写死。

**术语**：FAISS 一律称「向量索引／向量检索组件」；「向量」与「数据库」的连写在脚本里以拼接方式构造，免得验收脚本自己被术语检查命中（同 `验收第5阶段数据.py` 的 P 组做法）。

## `拼装第四阶段文档.py`

```powershell
python 工具\拼装第四阶段文档.py
```

读 `阶段04-系统总体设计\_分节源文件\` 的 7 个分节源文件，加文档头（元信息表、导言 第0.1节～第0.3节）与交付说明附录，写出 `阶段04-系统总体设计\10-系统总体设计（第四阶段）.md`。**《10》要改内容时改分节源文件再重跑本脚本，不要直接改交付文档**，否则下一次拼装会覆盖。

## 编写约定（改脚本时请遵守）

1. **检查项必须输出证据**（文件名加行号），不能只给结论——否则无法回溯。
2. **按文档分别归属节号**：`《02》第8.4节` 与 `《04》第8.4节` 是两个不同的节，不能放进同一个集合比较。第 3 阶段曾因混用集合而漏报一处未覆盖引用。
3. **修订留痕要排除**：`《02》` 的版本记录行与 `《05》`《06》 的"原为…"表述中会出现已作废的旧写法，那是留痕，不是缺陷。脚本据此把 **`05-`／`06-`／`08-` 三个记录类文件整体排除**在 `H`、`I` 两项之外——它们会逐字引用旧写法，不能当缺陷报。
4. `J` 与 `K` 是启发式检查，允许出现需要用人工判断的行，但**不允许静默跳过**——不确定就打印出来。
5. **计划产出要登记，且登记是「路径感知」的**：任务书一类文档会提到"将要创建"的文件（例如 `16-事件抽取与知识图谱（第六阶段）.md`），它在检查时必然还不存在。这类文件名写在脚本顶部的 `PLANNED` 集合里；**文件一旦创建就把它从 `PLANNED` 删掉**，否则会掩盖真正的悬空路径。`PLANNED` 分两类：**裸文件名**（`nodes.csv`、`验收第6阶段.py` 这种）在任意位置都算已登记；**带路径的**（`代码\抽取与图谱\README.md`）只匹配该路径。后者是 2026-09-25 加的——若把 `README.md` 按裸名登记，会连带跳过全项目所有 `README.md` 的悬空判定，副作用大于收益。当前 `PLANNED` 登记的是第 6 阶段的 12 项计划产出。
6. **查路径要知道数据集的存在**：第 5 阶段起文档会按**数据集内的相对路径**写文件（`meta\sources.csv`、`reports\consistency_report.md` 等）。`K` 项的 `SEARCH` 因此追加了 `阶段05-数据准备\数据集\<版本>\` 与 `_试跑\`；带省略号的 token（如正则片段 `cs.com.cn/….html`）由 `WHITE` 排除，因为它描述的是模式而不是具体文件。
12. **带路径的 token 必须按路径解析，不许退化成按文件名找**（2026-09-25 修）：`K` 原先对**所有** token 都追加一次"按文件名在全部搜索目录里找"的退路，于是 `代码\抽取与图谱\README.md` 因为 `代码\README.md` 存在而被判为"已存在"——**新目录下的 `README.md`／`config.py`／`run_all.py` 整类假阴性**。现改为只对**不含目录成分**的裸引用开放这条退路（文档里确实常有「见 `03-精选文献库（22篇）.md`」这种写法）。修完立刻暴露了 12 处此前被吞的引用，其中 9 处是 `文献调研/方向X_*.md` 这类别名——2026-09-25 重组时它们被迁进了 `_归档_*`，而 `legacy_paths` 只查阶段目录、没查归档目录，一并补上。**改动此类守卫后必须用负向用例验证它真的会报错**，不能只看到"全部通过"。
7. **不要在自己写的文档里逐字引用被 `I` 项禁止的那类句式**，哪怕是"未出现……"这种否定式引用：`I` 的判据是"含『每条关系』＋含证据属性字段名＋不含『除 EVIDENCED_BY 外』"，不区分引用与断言。第 4 阶段的交付说明里原有一张自检表逐字列出了该句式，因此被误报，最终把自检表从交付文档移到交付回复里。
8. **表格单元格里不要出现未转义的竖线**：`跨文档核验.py` 的表格列数检查按朴素切分计数，写成正则片段（如 `内部控制(评价|自我评价|审计)报告`）即使转义成 `\|` 也会被计成多列。第 5 阶段的《13》因此把完整模式集移到表格下方的代码块里，单元格只留文字说明。
9. **改《02》的版本号要改三处，并回头查引用方**：标题末尾、文档信息表的 `| 版本 |` 字段、第1.2节 修订记录新增一行——三处必须同时改，`N1` 项会核对。此外**引用《02》的文档**若声明了所依据的版本，该声明由 `N2` 审计：升了基线就要么同步引用方、要么在其依据行补版本链说明。这是 2026-09-25 补上的守卫：此前 v2.4／v2.5 只改了 第1.2节，标题与版本字段停在 v2.3，漂移了两个版本都没被任何检查发现；而 v2.6 升版当天又立刻让《09》《10》《12》的依据行过期——**这类问题靠人记是守不住的**。
10. **分段正则要能匹配到真正的结尾**：检查 `D`／`E`／`F` 依赖 `### 1\.3 需求来源清单` 的分段，原写法要求以 `\n---\n` 结尾，而《07》第1.3节 之后是 `## 二、` 标题、没有分隔线，**这三项曾长期静默跳过并报 OK**。现已改为 `(?:\n---\n|\n## )`。改动类似的"取段落"正则后，务必先确认段落真的非空再判定通过。
11. **移走或改名的文件由别名表兜底，不要回改历史记录**。2026-09-25 工作区按阶段重组后，`K` 项里有两张表：`LEGACY` 把旧目录前缀映射到新位置，`RENAMED` 把旧文件名映射到新文件名。记录类文档（《05》《06》《08》）里逐字保留着重组前的路径与文件名，那是历史留痕，**判据是"按别名能找到"而不是"把历史记录改成现在的样子"**。新增一次迁移时，先在这两张表里登记，再补《00》4.9 的对照行。

## 执行纪律（跨阶段通用，源自 2026-09-25 的历史复盘）

对照《05》（四轮评审）、《08》（两轮复核）、《11》（两轮复审）与第 5 阶段的实现记录，项目至今约 **110 项修正**可以归成八类。其中"同一口径多处不同步"约占四分之一，是最伤效率的一类，而且**机械可查**。下面七条是能固化成动作的部分，其余由本目录的脚本守住。

1. **改口径必须回归**（对应"修订本身引入新错误"，历史上栽过两次）。改任何一条冻结口径后必须做三件事：① 用关键字在**全部**文档里搜一遍它的旧写法，不许凭记忆；② 跑本目录的三套脚本；③ 在修订记录里写明"这条口径还被谁依赖"。教训：《08》第四节第 1 项为消除"六类／五项"不一致把计数改成"五类"，回原文核实后**真值是六类，改错了**；第 5 阶段为补窗口空洞引入分时段铺开，反而让最早一篇漂到 cutoff 前 86 天、违反了硬约束 13。

2. **可测性前置检查**（对应"设计了机制，却没验证它真能产生差异"）。任何进入实验设计的机制或开关，必须写出"打开与关闭时，**在哪一步**产生可观察差异"；写不出的不许进设计。教训：时间过滤被排在 K 截取之后、又写"不改变证据集合成员"，使 C 组与 D 组恒等，**H3 在定义上无法检验**——这是第 4 阶段最实质的缺陷；第 5 阶段又在数据侧犯了同构的错（时间窗中间整月为空，时序型题目没有 gold 证据）。

3. **数据集质量不只看条数**（对应"一篇文档吃掉整个索引"）。条数达标不等于数据集可用：第 5 阶段一度出现一篇 39.7 万字符的报告占全库 51.7% 的字符、单篇 1135 个文本块，会让 Recall@K／Precision@K 失去区分度。现由 `验收第5阶段数据.py` 的 `S` 组守卫（单篇 ≤ 25%、前 5 篇合计 ≤ 60%、跨公司同名标题）。

4. **篇幅预算前置**（对应"先写后压"）。动笔前先定图／表／行数上限，不要写完再压。教训：《10》一度写到 12 张图、55 张表，经两轮复审才压到 8 图 13 表，且最后仍留 1 张超出原定上限、需专门写裁决理由。

5. **开工先侦察**（对应"能力假设没有先验证"）。进入新阶段前，先把**环境能力 ＋ 外部依赖可达性 ＋ 数据源取数方式**验一遍再定方案。教训：第 5 阶段的四类数据源里三类是 JS 空壳（需另找 JSON 接口）、巨潮接口每页只回 30 条、FAISS 在中文路径下**必然失败**（须用 `serialize_index` 绕开）——这三条都直接影响架构选择，且都是先探查才发现的。

6. **脚本报错不等于文档有错**（对应"检查器也会误报"。与"编写约定 4"同源，但用在读结果时）。核验脚本本身是代码。判定前必须回原文。教训：《08》第三节 D5 的核验器报"矩阵来源越界 2 处"，回原文后确认 1 处是误报；`N2` 初版把同一行里不相干的版本号也算成《02》的版本，报出 19 处、实际只有 4 处——**守卫自己也要被校准，噪声大的守卫会被忽略**。

7. **"已完成"必须独立复现**（对应"自测在自己的夹具上做，夹具与实现可能同错"）。接受任何完成结论前，验收方要另走一条路径复现，不得采信自测报告。教训：第 5 阶段有执行者自报"幂等比对通过"，其中 `count 1` 其实是它脚本自身的 bug；FAISS 中文路径那条结论也是经独立复现才采信的。

## 作业纪律与执行助手

**这一节记的是「执行指令时踩的坑」，与上一节（项目本身的历史问题）不是一回事。** 2026-09-25 的执行复盘共列出 27 起失误：工具使用 12 起、判断与规格 12 起、环境不确定 3 起。**能机械修复的已固化进 `执行助手.py`；剩下几条写不进代码，只能靠动作。**

### 一、已机械化（用 `执行助手.py`，不要再手搓）

| 原来的失误 | 现在怎么做 |
| --- | --- |
| 用 PowerShell 解析 UTF-8 数据 → 被按 GBK 解码；更糟的是 `ConvertFrom-Json` 失败时**给出假结果**（实测 99 篇文档算成 `doc_id set identical = True (count 1)`，即"只有 1 条"却报"一致"） | 数据一律交给 Python：`执行助手.read_jsonl` / `read_text`。**不要用 PowerShell 解析 JSON** |
| 在 shell 里写代码 → 要过 PowerShell 与 Python 两层解释器，实测三次全中 | 逻辑一律落成 `.py` 文件；不再写 `python -c "…"` |
| 控制台默认 GBK → 中文全是乱码 | `执行助手.setup()` |
| 一次输出 120 KB → 冲掉大段上下文 | `执行助手.run()` 自动截尾，完整输出落盘并给出路径 |
| `git commit -m` 多行或含引号 → 被 PowerShell 拆成参数，报 `error: pathspec 'YYYY-MM-DD' did not match` | `执行助手.git_commit(消息)`，走 `-F 文件` |
| 中文路径被 git 输出成八进制转义 → `Test-Path` 报 `Illegal characters in path` | `执行助手.git()` 固定 `-c core.quotepath=false` |
| 推送盲试 → 每次白等 21 秒，实测两轮合计失败 11 次 | `执行助手.git_push()` 先探测连通再推（改后 4 轮内成功） |
| **扫描器假阴性** → `Select-String -SimpleMatch -AllMatches` 对一份**确实存在**该词的文档返回 0 命中，差点被当成"未出现禁用词"写进结论 | `执行助手.scan(..., control=…)` **强制正对照**：对照不命中直接抛 `ControlFailed`，因为那说明扫描器坏了，不是"没找到" |
| **逐处改文件改到一半失败** → 用 `edit` 逐处替换时，前面几处已落盘、后面某处锚点不匹配才报错，文件停在半改状态 | `执行助手.patch(path, [(旧, 新), …])`：**每一处都断言"只命中一次"**，任何一处不满足就整体放弃、一个字节不落盘；并把 N 处替换合成一次原子写 |
| **临时文件用固定名** → 第二次运行时该文件已存在，"覆盖已存在文件必须先读"的守卫拦住写入，报 `file has not been read` | `执行助手.tmp()` 返回**唯一**且已建好的空文件路径，每次都是新建 |
| **后台任务的输出只活在会话的 job 注册表里** → 注册表一回收就只剩 `Error: unknown job <id>`，那次运行的证据**永久丢失** | `执行助手.log_run(cmd, 日志路径)`：完整输出同时落盘，job 记不记得住都不影响回溯 |

另外两条与"读文件"有关，属于**只能靠动作**：
* **改之前必须在本会话读过该文件**。文件**刚被脚本重写过**（拼装脚本重写《10》、补丁脚本重写《02》）时，之前那条读记录会失效，必须**重读一次再改**——报 `file has not been read — read the file, then retry` 就是这个原因，重读即可，不是故障。
* **job 输出要用启动工具当次返回的 id**。界面上显示的长 UUID 与工具认的短 id（`pwsh-122`、`subagent-9` 这种）不是一套命名，从界面抄下来的 id 查不到。不确定就先 `job_list` 认一遍，别照着未知 id 反复重试。

### 二、只能靠动作（写不进代码）

1. **改口径前先 grep 依赖方**。12 起判断类失误里有 7 起是同一句话：**改一处，不看它还被谁依赖**。动一条冻结口径或一个数据格式之前，先用关键字把它的使用点列出来，再决定改哪几处。
   最新一次现场实例：给本助手新加 `tmp()` 时没查重名，而 `selftest()` 里早就有一个局部变量 `tmp`，被函数遮蔽后 `tmp(...)` 报 `TypeError: 'str' object is not callable`——**在写"防止改一处漏一处"的工具时，自己又犯了一次**。发现后先 `grep -w tmp` 列出全部 12 处使用点、再逐处改，一次改对。
2. **批量动作前先小样本试跑，并人工看一眼数据**。第 5 阶段那 6 个口径缺陷里有 4 个，只要先跑 1/10 规模就会当场暴露；它们是全量跑完才发现的，代价是"重采集 → 重切分 → 重向量化 → 重跑验收 → 同步文档"。
3. **"通过"必须独立复现**，不采信自测报告。执行者自报的"幂等通过"里，`count 1` 其实是它脚本自身的 bug。
4. **守卫精度要校准**。噪声大的检查会被忽略：新增的版本审计初版报 19 处、回查实际只有 4 处（同一行里不相干的版本号被算了进来），收紧口径后才可用。**第二次校准**发生在同一天稍后：另一个会话按 v2.6 把《12》的依据行改成了「（编制时为 v2.5，第 5 阶段完成后已登记为 v2.6）」——版本链已经讲清，但 N2 只认"版本链／未改变"几个字样，仍旧误报。补上"同行提到当前版本即可"之后，待处置项由 4 处收敛到 3 处。**两次都是修守卫，不是改文档。**
5. **环境能力先侦察再定方案**。第 5 阶段四类数据源里三类是 JS 空壳、巨潮接口每页只回 30 条、FAISS 在中文路径下必然失败——这三条都直接影响架构选择，且都是先探查才发现的。同时也要**及时止损**：当时顺手装了无头浏览器做兜底（约 150 MB），最后四类源全用 HTTP 解决，白装。
