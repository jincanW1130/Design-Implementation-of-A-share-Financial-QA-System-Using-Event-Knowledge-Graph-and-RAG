## 二、P0 严重 Bug

### Bug-1：后端进程在 Neo4j 不可达时崩溃退出
- **现象**：后端 8000 端口在 08:27:13 后突然失联，所有接口返回"无法连接到远程服务器"。
- **日志证据**：`后端启动_stderr.log` 末尾连续打印
  `WARNING 图谱后端不可用（SystemExit）：['Neo4j 连接失败（ServiceUnavailable）：bolt://127.0.0.1:7687']`
  紧跟 `ApiError GET /api/graph/entities/EVT-0824 → code=3001 http=503`。
- **根因推断**：图谱查询模块在 Neo4j 连接失败时抛出了 `SystemExit`（而非业务异常），该异常未被 FastAPI 异常处理器捕获，直接终止了 uvicorn worker 进程。
- **影响**：整个后端服务不可用，前端所有接口 500/失败，系统完全瘫痪。
- **建议修复**：在图谱模块的连接/查询层用 `try/except Exception` 包裹，将 `SystemExit` 转换为 `ServiceUnavailable`（code=3001）业务异常，不得让进程退出。

### Bug-2：前后端进程随启动窗口关闭而终止
- **现象**：08:36 实测时 5173 端口还在监听（pid=25572），08:37 再测已死；后端 pid 也在窗口关闭后消失。
- **根因**：`启动.ps1` 用 `Start-Process -WindowStyle Hidden` 启动的子进程，在父 PowerShell 退出后仍被连带终止（疑似作业对象未分离）。
- **建议修复**：用 `Start-Process` 时加独立进程分离，或改用 `pythonw.exe` / `nssm` 注册为后台服务；至少在 `启动.ps1` 末尾 `exit` 前确认子进程已 detach。

## 三、P1 功能/体验 Bug

### Bug-3：行情接口在外部源不可达时返回 500，而非优雅降级
- **现象**：控制台报 5 个 500 错误：`/api/config/meta`、`/api/health`、`/api/market/quote`、`/api/market/news`、`/api/market/reports`。
- **日志证据**：`实时行情取数失败：url=https://push2.eastmoney.com/... err=RemoteDisconnected: Remote end closed connection without response`。
- **根因**：后端调用东方财富 API 失败后，异常未被捕获为"行情未接入"的正常响应，而是冒泡成 500。
- **影响**：首页元信息行（语料截止/数据集版本/向量索引条数/维度）短暂全空，右上角"数据截至：-"显示短横线。
- **建议修复**：market 模块 catch 住所有网络异常，返回 `{ok:false, source:"未接入"}` 或 200 + 明确标记，与项目"行情源未接入"的设计口径一致。

### Bug-4：证据卡片重复，同文档多 chunk 未合并
- **现象**：/answer/40 的 9 条证据实际只来自 4 篇文档：
  - 证据 1/2/5：doc_id=1183（《接受注册通知书》公告）三个 chunk，标题完全相同
  - 证据 4/6/9：doc_id=2019（中报经营新闻）三个 chunk，标题完全相同
  - 证据 7/8：doc_id=1007（持股计划公告）两个 chunk，标题完全相同
- **影响**：用户看到大量重复卡片，以为召回了 9 篇不同文献；证据数虚高。
- **建议修复**：前端按 doc_id 分组，同文档多 chunk 折叠为一张卡片，标注"含 N 个片段"，或后端在装配证据时做 doc_id 去重。

### Bug-5：内嵌图谱可视化边标签重叠错乱
- **现象**：/answer/40 底部星型图谱中，红色边标签"参与·0.93""参与·0.95"等相互重叠，出现"参与·0参与·0.95"文字叠印。
- **附加问题**：图谱右上角有一个灰色空心五边形（POL-0048 政策节点），没有标签、没有连线，渲染异常。
- **建议修复**：边标签沿边中点错位摆放或使用防重叠布局；检查 POL-0048 节点为何渲染为无标签孤立形状。

### Bug-6：顶部通知条文字拼接不通顺
- **现象**：顶栏显示
  `● 语料截止 2026-09-25 · 数据集 v2.1 重跑采集与向量化前不变 | 实时区未接入 外部行情与新闻接口未接入：语料内近一周一块始终可用，见屏①[实时区]·三块数据源`
  - "语料内近一周一块始终可用"语句不通（疑为"内容"漏字）
  - "见屏①"引用标记突兀，无对应锚点
  - 两段状态信息用 `|` 分隔但视觉上挤在一起
- **建议修复**：拆分两条独立通知条或加明确分隔符；修正文案。

### Bug-7：历史记录页统计卡片字段错位
- **现象**：/history 页四个统计格中，第三格"图谱深度上限"的值显示为"标记载荷"（label 文字），而非数字（应为"2 跳"或类似值）。
- **建议修复**：检查该卡片 value 字段的渲染绑定，疑似把 label 当 value 渲染。

### Bug-8：图谱节点/边只显示技术 ID，无人类可读名称
- **现象**：图谱路径卡片和可视化中，节点显示为 `600887`、`EVT-0236`、`POL-0048`，边显示为 `PARTICIPATES_IN`、`RELATED_TO`。
- **影响**：用户不知道 600887 是伊利股份、EVT-0236 是什么事件。
- **建议修复**：前端在渲染时根据节点 ID 查询实体名称（公司名/事件标题）做映射显示；边类型映射为中文（如 PARTICIPATES_IN → "参与"）。

### 7.6 误报澄清：孤立政策节点 POL-0048 为正常节点
