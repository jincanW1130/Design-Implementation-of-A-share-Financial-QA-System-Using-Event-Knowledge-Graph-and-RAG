# 02-探索性测试（Exploratory Testing）

> 建立于 2026-10-11，对应《2026-10-11-全栈测试与代码审查报告》问题 S9（探索性测试零记录，判「不通过」）。

## 制度

**charter（章程）**是探索性测试的最小组织单元，每份 charter 含五要素：

1. **探索（Explore）**：测什么目标；
2. **使用（With）**：什么资源／方法；
3. **关注（To discover）**：什么风险或信息；
4. **时限（Timebox）**：一轮探索的预算（本项目：30 分钟级，脚本化 charter 可重放）；
5. **产物**：执行记录 ＋ 发现登记（缺陷／观察／疑问三类，**如实登记，不编造结论**）。

## 编制纪律

- 探索的产物是**发现**，不是断言——「探索无恙」也是有效结论，但必须写明探索了什么、
  没探索什么（防「看起来测过」的假象）；
- 每条发现带证据路径（`_证据/` 下的执行记录文本）；
- charter **只追加、就地更新状态**（待执行 → 已执行 → 待复验），不重写历史记录；
- 可脚本化的 charter 把执行器一起入库（可重放＝可回归），本目录的执行器落
  `.workbuddy/test-audit/`（与审计测试同点，避免混入产品测试套件）。

## 与其他资产的关系

- 确定性回归（单元／门禁／冒烟）负责「已知怎么测」的部分；charter 负责「不知道哪里会坏」
