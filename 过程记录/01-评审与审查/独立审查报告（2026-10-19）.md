**位置**

  `data-ctxfor` 的查找改用 `findByData`（消除“恶意值导致 `querySelector` 语法错误”的次级问题）。
- `GraphView.vue:29` 引入 `esc`，`:277` 月份刻度、`:284` `data-dot` 均已转义。

### P1-4 备份脚本对 root／DDL 权限的硬依赖

**位置**

- `工具\备份.py:146-186`（`_preflight_verify_db`）
- `工具\备份.py:287-288,342-364,391-392,428-429,506-509`

**问题**

备份的「导入回验」需要临时库 `ashare_qa_bakverify_<stamp>` 的 `CREATE/DROP DATABASE`。
DML-only 运行期账号没有该权限，原流程会在生成 dump 之后才失败，既不给出可执行路径，也可能
留下「看似成功、实际未回验」的半成品语义。

**修复**

- 在创建输出目录、写任何文件之前做**权限预检**：建/删探针临时库，失败立即退出 1，不产生输出目录。
- 明确两条可执行路径：
  1. 用迁移账号执行完整「备份 + 导入回验」；
  2. 没有迁移账号时显式 `--skip-verify`：仍生成 dump／Neo4j／向量备份，但 manifest 如实写
     `verify.skipped=true` 与 `reason`，最终结论显示「备份文件已生成，但**未做导入回验**」。
- 文档同步：`交付物\10-部署\安全加固与最小权限清单.md:103-104,126` 增加临时库授权语句与
  `--skip-verify` 语义。

**复现证据**

```powershell
python 工具\备份.py                 # DML-only：预检失败，exit 1，未创建输出目录
python 工具\备份.py --skip-verify   # exit 0，manifest verify.skipped=true
```

- `--skip-verify` 实测六表计数 30/30/293、709/5018，Neo4j 3607/3614，备份文件 6 个。
- 用迁移账号（从 `config.local.json.bak-*` 程序化注入环境变量，未打印凭据）完整回验：
  exit 0，`counts_match=True`，临时库已删除；事后查询 `ashare_qa_bakverify%` 残留 0 个。
- 因此备份**不再硬依赖 root**：DML-only 可生成备份；完整回验需迁移账号或显式跳过。

**处置**：P1，已修复；默认命令在 DML-only 下仍会快速失败（运维口径见 P2-6）。

### P2-4 指标窗口「300 s」与实际读取上界 360 s 不一致

`s[0] >= now - HISTORY_SECONDS`，或在 `snapshot()` 内先按当前时间裁剪；补一个“空闲 330 s 后
snapshot 不应包含 300 s 以前样本”的测试。
