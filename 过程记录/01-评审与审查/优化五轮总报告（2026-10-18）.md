## 三、每轮做了什么

### 第 1 轮 · 性能优化

- **落地**：
  - `graph_service.event_chunk_ids_batch()`：G6 由逐事件 N+1 改为一条 `IN $ids` 批量取块；
  - `api/graph._path_payload(..., brief_map)`：路径节点简述批量取回，消除逐节点 `brief()`；
  - `/api/admin/extraction/events`：先分页、只为当前页算证据文档数；
  - MySQL 索引/语句核查、向量检索耗时实测、Prompt Token 与 LLM 耗时实测。
- **关键读数**：G6 **1244.35 → 65.83 ms**（批量取块 571.42 → 7.73 ms）；路径整形
  **81.0～129.5 → 约 3.3 ms**；路径时间窗 **80.8～104.4 → 0.05 ms**；后台事件证据计数
  **37.33 → 2.50 ms**；MySQL 高频语句平均 0.114～0.469 ms；相关子查询 0.336～0.666 ms，
  JOIN 改写 4.165～7.106 ms（保留子查询）。
- **方案**：读写分离、多级缓存、HNSW/IVF、语义分块、结果缓存/异步、高可用与熔断；
  写入 `交付物/05-系统实现/性能与架构优化方案.md`。

### 第 2 轮 · 代码质量与架构

- `main.py` **494→190 行**；新增 `params.py`（统一参数校验）、`middleware.py`（限流/守卫/安全头）、
  `probes.py`（健康探针）；`api/*` 不再反向依赖 `main`。
- `errors.py` 引入 `contextvars`＋请求 ID（进日志与响应头，不进响应体）。
- `config.py` 新增 `API_LIMITS`，取值未改；分页/长度/图查询缺省值收敛。
- 图谱后端 `if/else` 收敛为 `BACKEND_FACTORIES` 注册表＋`register_backend()`。
- **证据**：293 passed 不变；重复率 0.8%；依赖方向违规 0；错误体仍恰为 `{code,message}`。

### 第 3 轮 · 业务体验、数据与安全

- 同会话重复提问幂等复用（`reused=true`，0.02 s，不重复调模型）。
- 前端 320 s 超时与「取消等待」；如实提示「后端可能仍完成」。
- 会话隔离/重置；历史页展示当前会话号；修正空态无效指引。
- 权限矩阵：无令牌 401/4001、普通用户 403/4002、正确令牌 200/404；跨会话读 404/2001。
- 安全：SQL 注入探针 0 命中；v-html 使用点安全；CORS 白名单；安全头；70 KiB 请求体拒绝；
  限流第 60 次后 429/1004＋`Retry-After: 60`。
- 数据质量：document 709／document_chunk 5018；重复/孤儿/空块等均为 0；
  图谱 3607 节点／3614 边；孤立节点 587、重复事件名 3 组（按约束只登记不清理）。
- **遗留**：多轮上下文未做；增量更新不自动；数据库 root 权限与明文配置待后续。
