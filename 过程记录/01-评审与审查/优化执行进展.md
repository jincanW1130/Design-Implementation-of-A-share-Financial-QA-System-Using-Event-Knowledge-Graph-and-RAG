## 项目速览

- 题目：基于事件知识图谱与 RAG 的 A 股财经信息智能问答系统（本科毕设）
- 栈：Vue 3 ＋ Vite 6.4.4 ｜ FastAPI ＋ MySQL 8.4.9 ＋ Neo4j ＋ FAISS ｜ deepseek-flash ｜ 本地 `BAAI/bge-small-zh-v1.5`
- 布局：`交付物/03-代码/{数据准备,抽取与图谱,检索,问答,后端,前端}`、`交付物/04..06` 数据与实验、`工具/` 门禁、`过程记录/` 记录
- 关键入口：后端 `交付物/03-代码/后端/run.py`（:8000）；前端 `cd 交付物/03-代码/前端; npm run dev`（:5173）
- 门禁：`工具/跨文档核验.py`、`验收第5/6/7/8/10/11阶段.py`、`工具/拼装第十一阶段论文.py --check`
- 已知设计：问答链路为重资源子进程（每条 ask 都加载 BGE 模型），后端用 `_ASK_LOCK` **串行化**；
  `/api/rag` 等接口有 60 次/60 秒限流（`ASHARE_RATE_LIMIT_MAX` 仅供本地压测放宽）。

### 一、性能优化（系统运行速度、资源消耗）
**1. 数据库优化（MySQL）**
1. 索引设计：区分主键、唯一索引、普通联合索引；避免索引失效场景（函数运算、隐式转换、like 前缀 %）；定期分析慢查询日志，删除长期不用的冗余索引，索引不宜过多，会降低写入速度。
2. SQL 优化：禁止 `select *`，只查询业务需要字段；减少嵌套子查询，改用 JOIN；避免大事务，缩短事务执行时间；大表采用分页、游标分页，防止一次性拉取海量数据。
3. 表结构优化：合理选择字段类型，比如用 tinyint 代替 int，varchar 合理限制长度；拆分大表，冷热数据分离，历史财经事件归档到归档表。
4. 读写分离：查询量大时，主库写，从库读（毕设可选，可写在方案里）。

**2. 缓存体系优化（Redis）**
1. 多级缓存：本地内存缓存（Caffeine）＋ Redis 分布式缓存，热点数据先读本地。
2. 缓存策略：合理 TTL，区分永久/短期；解决穿透（空值缓存、布隆过滤器）、击穿（互斥锁、热点永不过期）、雪崩（过期时间随机偏移、集群高可用）。
3. 缓存预热：启动时预加载高频财经实体、常用问答结果。
4. 更新策略：Cache Aside，保证一致性。

**3. RAG 与知识图谱专属计算优化**
1. 文档预处理：调优分块策略（块大小、重叠窗口）；过滤低质量文本/空白段落/无效表格；支持语义分块而非纯字符切割。
2. Embedding：批量向量化、缓存已向量化片段、轻量模型或量化。
3. 向量检索：索引选型（HNSW/IVF）、调 TopK 与 ef、向量库分片、过滤无关向量以减少上下文。
4. 图谱查询：实体/关系索引；简化 Cypher；避免深度递归；结果缓存。
5. LLM：裁剪 Prompt；结果缓存；异步调用；合理超时。

**4. IO、网络、并发**
1. 文件 IO：流式读取；解析任务异步化；冷热文件分离/对象存储。
2. 网络：连接池复用；连接/读取超时；指数退避重试。
3. 并发模型：线程池/协程池；区分 IO 与 CPU 密集；读写锁；限制最大并发。
4. 异步任务队列：耗时任务入 MQ 削峰（文档解析、入库、图谱更新、向量入库），不阻塞问答接口。

### 二、代码质量优化
1. 重构坏味道：拆分超长函数/巨型类，单一职责；消除重复；删死代码与无效 import。
2. 消除魔法值：常量集中，禁止硬编码模型地址/阈值/topk。
3. 统一参数校验：非空、长度、格式；统一错误信息。
4. 异常体系：业务异常与系统异常分离；不大范围 try-catch；异常带请求 ID；不向前端抛原始堆栈。
5. 代码规范：Lint 静态检查（空指针、资源泄漏、不规范写法）；统一格式化。
6. 资源释放：DB 连接、文件流、网络连接自动关闭。

### 三、架构优化
1. 分层强化：Controller → Service → Mapper/DAO → 存储，禁跨层。
