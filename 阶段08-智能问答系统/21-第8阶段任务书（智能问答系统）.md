## 一、阶段界定

### 1.1 本阶段与相邻阶段的边界（必须先讲清，否则会与《02》第16.1节 冲突）

第 1～7 阶段已全部完成并各自通过门禁：数据集 v2.1（709 篇文档／5018 个文本块）、现行图谱导出 `v2.1_v1_2`（2802 节点／2736 边）、四项定值 K = 10／N = 20／Context Token Budget = 3600／g = 2。第 7 阶段的链路**不调用答案生成模型**，只到「最终证据集合 ＋ 图谱载荷 ＋ 适配接口」为止。

本阶段处理的**只有一件事**：把「检索结果 → Prompt → 大模型 → 带证据的答案」这一段做成可运行、可复现、可门禁、可被第 9 阶段直接接线的**答案生成层**。对应《07-需求分析》的 **FR-04 智能问答**、**FR-05 证据追溯** 与 **FR-06 历史问答** 三个功能需求，以及《10-系统总体设计》第4.3.1节 的流程一（提问问答）、第4.6.8节 的 Prompt 结构（表 4-12，版本 v1.0）、第4.6.9节 的图谱路径输出条件、第4.4.7节 的 `answer.graph_path` 存储形式。

| --- | --- | --- |
| 上游（已完成，只读） | 最终证据集合（`per_question_trace.jsonl` 的 `final_evidence_chunk_ids`，≤ K = 10）、图谱载荷（`graph_payload`）、token 分账（`token_account`／`segments`）、《19》第9.1节 的「检索结果 → Prompt 区块」适配接口 | 第 7 阶段 |

**一句话边界**：本阶段交付的是「**能对着冻结证据集合生成带引用编号的答案，并把答案与证据绑在一起落成可回看记录**」的组件与证据；第 9 阶段把它接到服务与页面上，第 10 阶段用它跑正式实验。

### 1.2 本阶段在实验设计里的位置（不得越界的一条）

答案生成侧**不是实验变量**：《02》第12.4节 要求所有对比组与消融组使用相同的大语言模型、相同版本、相同 temperature、相同 Prompt 版本与相同 Context Token Budget。因此本阶段落地的模型、版本、temperature、Prompt 版本一经冻结，**A～E 五组共用同一套**；第 10 阶段的指标差异只能归因到检索侧开关，不得归因到生成侧。

本阶段**不产生实验结论**，也不得把 30 题预实验集上的任何读数写成正式实验结果（题集纪律见《19》第9.2节 第 1 条）。

### 2.3 本阶段必须遵守的硬口径（一律以《02》为准，本阶段不重新论证）

1. **四项定值不得改动**：K = 10／N = 20／Context Token Budget = 3600／g = 2；`g` 是全局固化量（A～E 同值、不进任何开关），下限 `g ≥ 1`。
2. **分层保留顺序**（第③步裁剪与第④步保留 K 共用）：向量侧按原始排名取前 (K−g) → 图谱侧新增块按对问题的向量相似度降序至多 g → 向量侧剩余候选回填；D 组的呈现顺序就是它。
3. **C 组 ＝ Method**（向量 RAG ＋ 2 跳事件 KG），A 组 ＝ Baseline 2；**D ≡ E** 逐题成立（集合相同、只有顺序不同）。
4. **0 跳或未启用图谱扩展时**：`answer.graph_path` 为空、`is_graph_extended = 0`，页面与答案**显式标注「本次回答未使用图谱扩展」**，不得生成虚构图谱路径（《02》第13节；《10》第4.6.9节）。
5. **MySQL 恒为六张表**（user／document／document_chunk／question／answer／answer_evidence），本阶段不写任何 DDL、不建库、不起服务；`data_cutoff_time` 不属于任何表；`session_id` 是 question 表的字段而不是新表。
6. **本课题未部署 Neo4j 服务**：图谱侧是「查询层 ＋ 内存图」；论文与文档如实说明实现形态，不得声称已部署。
7. **术语纪律**：FAISS 一律称「向量索引」或「向量检索组件」，不得写成被禁的四字连写；不得出现被禁术语的任何变体。
8. **公开事实与模型分析必须区分**：开放式分析问题在页面与答案中同屏标注「模型分析（非公开事实）」，且不计入任何指标（《02》第12.9节）。

## 五、编写口径与硬约束（可机器核验）

1. **参数一律取 `config.py`**：脚本内不得写死模型名、端点、路径、温度、Prompt 版本、日期或阈值。
2. **模型与版本**：`model_name = "deepseek-flash"`、`model_version = "deepseek-flash"`（端点 `/models` 的实测 id）、`temperature = 0`、`endpoint = "https://api.deepseek.com/v1"`、`max_tokens = 16384`；前四值与《02》v3.3 登记逐字一致，`max_tokens` 是**答案侧生成配置**（《02》第12.4节 只冻结模型、版本、temperature、Prompt 版本与四项检索定值，不冻结输出上限），**A～E 五组同值**，不得随组变化。
   **`max_tokens` 的定值依据（决策者 2026-09-29 实测）**：本端点上的模型是**推理型**（响应带 `reasoning_content`），推理 token 与正文 token **共用**该上限。实测（`_工作底稿\决策者核验\max_tokens_复测.json` 与 `max_tokens_上限复测.json`）：`max_tokens=2048` 时 30 题里有 6 题的正文被推理吃光而成空串（`finish_reason=length`）；`4096` 仍有截断；**`16384` 下最吃推理的 PE-14 也稳定 `finish=stop`、正文非空（实测 completion 2041～2884）**，且端点接受该取值（32768 亦被接受，但不取更大值以免无谓拉长生成）。因此取 **16384**。
   **空正文的重试规则（技术稳健性，不是变量）**：若某次请求返回**空正文**（`content` 为空串），以**完全相同的配置**重试一次，并把两次尝试都落进 `answer_trace.jsonl`；两次都为空则该题判失败、脚本非零退出，**不得**写入空答案。该重试对 A～E 五组一律适用。
3. **Prompt 版本**：`PROMPT_VERSION = "v1.0"`，模板文本与版本号绑定在同一文件；模板与配置分离；实验中所有组共用同一版本。
4. **Prompt 七区块**：系统角色与任务边界／数据版本与时间边界／问题／文本证据／图谱路径与事件三元组／相对时间判定说明／输出格式要求——**顺序固定、不得增删区块**；第 2 区块**每次请求都注入** `dataset_version` 与 `data_cutoff_time`；第 3 区块不得改写或扩写用户问题。
5. **证据顺序不得在生成侧重排**：C 组（及 D 组）文本块顺序 ＝ trace 的 `final_evidence_chunk_ids` 顺序；E 组另按 `evidence_sort` 的可解释因素排序；生成侧只做呈现，不新增排序规则。
6. **预算不突破**：文本块 ＋ 图谱路径 ＋ 事件三元组 ≤ 3600 token；第 8 阶段**不重新裁剪**，直接消费第 7 阶段已裁剪到预算内的集合；若装配后超预算（例如图谱路径读数与 token 估算口径不同），必须报错退出并如实登记，不得静默截断。
7. **图谱载荷原样透传 ＋ 由代码拼装、不由模型自述**：`graph_payload` 的 `graph_path`／`event_triples`／`graph_used` 三项**一个字段都不加工**，直接写入 `answer.graph_path` 与答案的图谱段（《19》第9.1节 第 2 条）。**答案的四个区块里只有「回答」正文由模型生成**；「证据来源」「知识图谱路径（或未使用图谱扩展的标注）」「数据截至与判定区间」三段由代码**确定性拼装**（证据段来自本次证据集合与语料元数据，图谱段直接取 `graph_payload`，时间段取 `dataset.json`）——模型不得自行罗列证据清单、不得自行描述图谱路径。理由：FR-05 要求证据列表来自 `answer_evidence`、图谱路径来自 `answer.graph_path`，若交给模型自述，这两项就退化成模型措辞而不可核验（T2 小样本试跑已实测到该风险：有候选在同一题上把用了图谱扩展的题写成「本次回答未使用图谱扩展」）。
8. **「未使用图谱扩展」的显式标注**：当 `graph_used` 为假时，`graph_path` 为空、`is_graph_extended = 0`，答案的证据区块出现固定字样**「本次回答未使用图谱扩展」**；不得留空、不得展示虚构图谱路径。该字样**只允许出现在系统拼装的图谱段里**；模型生成的「回答」正文中出现该字样即判失败（说明模型在自述检索过程）。
9. **引用编号纪律**：答案正文中的引用记法固定为 `[证据n]`，`n` 为本次证据集合中按呈现顺序的序号（1 起）；出现 `n > |E|` 或 `n < 1` 即判失败。
10. **日期纪律（证据里明写的日期不算越界，凭空的日期算越界）**：答案中出现的任何年月日，必须满足**至少一条**：① 在本题证据集合的正文里**字面出现**；② 等于 `data_cutoff_time` 的日期部分；③ 是由 `data_cutoff_time` 按第 11 条窗口规则**确定性推出**的判定区间端点（「最近」＝截止时间前 30 天、「近期」＝前 90 天）。三条都不满足即为**越界**，越界 0 次是门禁。**证据正文中明写的、晚于 `data_cutoff_time` 的日期不算越界**——例如公告原文写明的「行权期有效期至 2027-01-25」，它是公开事实的原文，不得要求模型隐瞒，也不得判为幻觉；但答案不得据此推断数据截止之后**新发生**的事（这一条属论文层面的表述纪律，见第 11 与 12 条，机器只核日期来源）。
11. **「最新／最近／近期」一律按 `event_time` 判定**，判定基准是 `data_cutoff_time` 而不是系统运行当天；「最近」＝截止时间前 30 天、「近期」＝前 90 天。
12. **开放式分析问题**必须带「模型分析（非公开事实）」标注，且不计入任何指标；识别依据是题集的标注字段，不得靠关键词猜测。
13. **记录层字段名以《10》第4.4.1节 表 4-6 为准**：question 的 `question_id`／`session_id`／`question_text`／`task_type`／`gold_hop_depth`／`time_constraint`／`ask_time`；answer 的 `answer_id`／`question_id`／`answer_text`／`graph_path`／`model_name`／`prompt_version`／`is_graph_extended`／`create_time`；answer_evidence 的 `answer_id`／`chunk_id`／`doc_id`／`rank`／`evidence_type`——**不新增字段、不改字段名**；JSONL 里的嵌套只是形态，字段语义不得变。
14. **`(answer_id, chunk_id)` 联合唯一**（同一答案下同一文本块只一条记录）。
15. **`evidence_type` 取四类之一**：回答来源／新闻来源／公告来源／相关事件；分类依据是文档的 `category` 与「是否来自图谱侧」，不得自造类别。**映射表按数据集 v2.1 的真实类别词表逐项写死**（决策者 2026-09-29 实测：全语料 `category` 只有「公告」556／「财经新闻」103／「政策文件」30／「监管公开信息」20 四种）：
    | 文档 `category` | `evidence_type` | 理由 |
    | --- | --- | --- |
    | 公告 | 公告来源 | 官方披露文本 |
    | 政策文件 | 公告来源 | 官方全文发布，与「公告」同属官方发布文本 |
    | 监管公开信息 | 公告来源 | 监管机构的公开信息，同为官方发布 |
    | 财经新闻 | **新闻来源** | 新闻媒体文本 |
    | 缺失／其它 | 回答来源 | 兜底类 |
    | 来自图谱侧新增块（`from_graph`） | 相关事件 | 与前三类的区分维度是「是否来自图谱侧」 |
    **反例（本次实测发现，已修）**：映射表原先把键写成「新闻」，而数据里的真实取值是「财经新闻」，于是**新闻类证据全部落到兜底类「回答来源」、`新闻来源` 出现 0 次**——键名必须与数据真实取值逐字对齐，改完须逐类复核计数（本批 30 题应能观察到 `新闻来源`）。
16. **历史问答**：第一版不启用登录，按 `session_id` 过滤；不同会话互不可见；回看只还原 question／answer／answer_evidence 的内容，**不重新渲染图谱路径**。
17. **应答确定性**：装配层（证据 → Prompt 文本）在同一输入下**逐字节一致**；模型侧输出**不承诺**逐字节一致，改为如实登记两次运行的重复一致率。
18. **模型调用计数**：每次调用计入 `run_manifest.json`；`STAGE8_FORBID_MODEL_CALLS=1` 时调用次数必须为 **0** 且链路在 `--dry-run` 下跑通。
19. **密钥纪律**：不写死、不回显、不入库、不进日志；缺失即以明确错误退出。
20. **术语纪律**：FAISS 只称「向量索引」；不得声称部署 Neo4j 服务；不得引入《02》第8.4节 之外的技术；不得新增第三个数据存储、不得新增表、不得引入第四个可变参数。
21. **不引入新的实验变量**：A～E 五组共用同一模型、版本、temperature、Prompt 版本与预算。
22. **对输入只读**：第三节 的八项在开工与收工两次指纹比对必须逐项一致；`代码\检索\` 的脚本与 `检索产出\` 的产物**一个字节都不改**。

## 六、我已预先定下的格式决策

以下八条由决策者在开工前定下，执行者不再另行选择：

3. **引用记法**：`[证据n]`，n 为本次证据集合中的呈现序号（1 起），与 `answer_evidence.rank` 一致。
4. **标识生成规则**：`question_id`／`answer_id` 由确定性规则生成（`Q-001`…／`A-001`…，与题集 `PE-nn` 一一对应并落进记录），`session_id` 由命令行给定、缺省为固定值；不使用随机数或时间戳参与 ID。
5. **记录时间字段**：`ask_time`／`create_time` 由 `--now` 注入（缺省取运行时刻）；做复现性比对时必须显式传固定值。
6. **组别缺省**：`--group` 缺省 **C（Method）**；A～E 均可运行，但**本阶段录制的正式留痕是 C 组 30 题**。
